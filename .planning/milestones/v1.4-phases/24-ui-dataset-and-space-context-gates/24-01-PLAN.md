  <action>
Import localStorageUtils at the top of the file:
```
import localStorageUtils from "utils/storageUtils/localStorageUtils";
```

In BOTH `newMenuDropdown()` and `oldMenuDropdown()` methods, add a permission check at the start of each method, right after the existing destructuring:
```javascript
const isAdmin = localStorageUtils.isUserAnAdmin();
const entityPermissions = entity.get("permissions");
const hasAlter = isAdmin || entityPermissions?.get("canAlter");
const hasDelete = isAdmin || entityPermissions?.get("canDelete") || entityPermissions?.get("canAlter");
```

Then modify the conditional rendering of menu items in BOTH methods:
1. **Edit**: Change `{canEdit && (` to `{canEdit && hasAlter && (` -- non-admin users need ALTER to edit a VDS
2. **Rename**: Change `{canMove && (` (for Rename) to `{canMove && hasAlter && (` -- non-admin users need ALTER to rename
3. **Move**: Change `{canMove && (` (for Move) to `{canMove && hasAlter && (` -- non-admin users need ALTER to move
4. **Settings**: Change the unconditional `<MenuItemLink ... text={t("Common.Settings")} />` to be wrapped in `{hasAlter && (<MenuItemLink ... />)}` -- settings exposes alter-like operations
5. **Delete**: Change `{canDelete && (` to `{canDelete && hasDelete && (` -- non-admin users need DELETE or ALTER to delete
6. **Remove Format**: Change `{canRemoveFormat && (` to `{canRemoveFormat && hasAlter && (` -- remove format is an alter operation
7. **Also update the divider**: The divider `{(canRemoveFormat || canDelete) && <DividerHr />}` should become `{((canRemoveFormat && hasAlter) || (canDelete && hasDelete)) && <DividerHr />}` so it does not render a trailing divider when all items below it are hidden.

Leave Query, Open Details / Details, Go To Table, Analyze, and Copy Path unconditionally visible -- these are read-only actions.

IMPORTANT: Apply identical logic to BOTH `newMenuDropdown()` and `oldMenuDropdown()` methods. They are selected at render time by `shouldUseNewDatasetNavigation()`.
