<objective>
Fix the login endpoint to return RBAC-aware admin status and session permissions, so that the frontend's existing permission gates (Add Source, Add Space, Settings route guard, Users page) correctly hide controls from non-admin users.

Purpose: The root cause of UI-01, UI-02, and UI-03 is that LogInLogOutResource.java hardcodes admin=true and all SessionPermissions to true for every user, regardless of their actual RBAC role membership. The frontend already has the correct guards in place (useCanAddSource, UserIsAdmin wrapper, getAddSpaceHref admin check) but they are ineffective because the backend always says "yes."

Output: A single backend file change that makes the login response RBAC-aware, immediately fixing all three UI permission gates.

  <action>
Modify the `login()` method in LogInLogOutResource.java to determine actual admin status via RbacService before constructing the login response.

**Step 1: Get RbacService access.**
The `dContext` (SabotContext) is already injected. Access the RbacService through `dContext.getAccessControlListingManager()` and cast it, OR use the same provider pattern that RbacResource uses. The safest approach is to check if RBAC is enabled first:

```java
// After authenticating the user (after line 105), determine admin status:
boolean isAdmin = true; // default to true when RBAC is disabled (backward compatible)
try {
  com.dremio.exec.rbac.RbacService rbacService =
      (com.dremio.exec.rbac.RbacService) dContext.getAccessControlListingManager();
  if (rbacService != null) {
    isAdmin = rbacService.isAdminMember(userConfig.getUserName());
  }
} catch (Exception e) {
  // If RBAC service is unavailable, default to admin=true for backward compatibility
  logger.warn("Could not determine admin status via RBAC, defaulting to admin=true", e);
}
```

Note: If `getAccessControlListingManager()` is not available on SabotContext, check for an `rbacServiceProvider` or inject `javax.inject.Provider<RbacService>` directly. Search the codebase for how `RbacResource.java` accesses the RbacService (it uses `@Inject Provider<RbacService>`).
