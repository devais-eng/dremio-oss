<objective>
Close the two critical write-path authorization holes in the v3 API: the User API allows any authenticated user to create/update users, and the Catalog API allows any authenticated user to create/update/delete/promote catalog items without privilege checks.

Purpose: Prevent non-admin users from escalating privileges via User API and unauthorized mutation of catalog objects via Catalog API.
Output: Hardened UserResource.java with admin-only write methods, and CatalogServiceHelper.java with per-entity-type RBAC privilege enforcement on all mutation paths.
</objective>

private void enforceCreatePrivilege(CatalogEntity entity) {
  if (rbacService == null || dremioConfig == null
      || !dremioConfig.getBoolean(DremioConfig.RBAC_ENABLED)) {
    return; // RBAC disabled
  }
  String userName = securityContext.getUserPrincipal().getName();
  if (rbacService.isAdminMember(userName)) {
    return; // admin bypass

  if (entity instanceof Space) {
    throw UserException.validationError()
        .message("Permission denied: only administrators can create spaces.")
        .buildSilently();

    if (!rbacService.hasPrivilege(userName, "CREATE_VIEW", "SPACE", parentPath)) {

    return;
