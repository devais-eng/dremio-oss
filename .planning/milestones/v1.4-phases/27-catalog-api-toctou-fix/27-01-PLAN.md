Output: Patched CatalogServiceHelper.java with ALTER check before rename + integration test proving the fix.

  <name>Task 1: Move ALTER privilege validation before rename in updateNonVersionedDataset()</name>
  <files>dac/backend/src/main/java/com/dremio/dac/service/catalog/CatalogServiceHelper.java</files>
  <action>
In `updateNonVersionedDataset()`, the VDS branch (starts at line 1853 `else if (dataset.getType() == Dataset.DatasetType.VIRTUAL_DATASET)`) currently has the ALTER privilege check at line 1885 AFTER the rename block at lines 1858-1863. Fix:

1. Move the `catalogSupplier.get().validatePrivilege(namespaceKey, SqlGrant.Privilege.ALTER)` call to BEFORE the rename block, immediately after `VirtualDataset virtualDataset = currentDatasetConfig.getVirtualDataset();` (after line 1855). This ensures:
   - If the user lacks ALTER privilege, the exception is thrown BEFORE `datasetVersionMutator.renameDataset()` executes
   - If the user lacks ALTER privilege, the exception is thrown BEFORE `virtualDataset.setSql()` mutates anything
   - If the user HAS ALTER privilege, execution continues to rename + update as before

2. Remove the duplicate `catalogSupplier.get().validatePrivilege(namespaceKey, SqlGrant.Privilege.ALTER)` at the old location (line 1885) since it is now checked earlier. The privilege check need only happen once.

3. Update the comment. Replace the old comment "// RBAC: enforce ALTER privilege on the view being updated" (line 1884) — since the check is moved up, add a comment at the new location: "// RBAC: enforce ALTER privilege before any mutation (rename, SQL update)"

4. Keep the `namespaceKey` construction at line 1777 (`new NamespaceKey(dataset.getPath())`) as-is. This uses the REQUESTED path (which may differ from current). For the privilege check, we want to validate against the CURRENT dataset's namespace key to prevent privilege escalation via path manipulation. So the validatePrivilege call should use `new NamespaceKey(currentDatasetConfig.getFullPathList())` (the current path) rather than `namespaceKey` (the requested/new path). This prevents a scenario where a user has ALTER on a target space but not on the source, and tries to move a dataset to a space they control.

The resulting code order in the VDS branch should be:
```
Preconditions.checkArgument(type == VIRTUAL_DATASET, ...)
VirtualDataset virtualDataset = currentDatasetConfig.getVirtualDataset();
// RBAC: enforce ALTER privilege before any mutation (rename, SQL update)
catalogSupplier.get().validatePrivilege(new NamespaceKey(currentDatasetConfig.getFullPathList()), SqlGrant.Privilege.ALTER);
// Check if the dataset is being renamed
if (!Objects.equals(...)) { datasetVersionMutator.renameDataset(...); ... }
virtualDataset.setSql(dataset.getSql());
...
catalogSupplier.get().updateView(namespaceKey, view, viewOptions, attributes);
```

Do NOT touch the PDS branch (physical datasets cannot be renamed — guarded at line 1784).
Do NOT touch the versioned dataset path (rename is already disallowed at line 1636-1639 and ALTER check at line 1662 is fine since no mutations precede it).
Do NOT touch the `enforceUpdatePrivilege()` helper at line 1332-1334 — its early return for Dataset is still correct since the real check now happens early in `updateNonVersionedDataset()`.
