# Requirements: v1.2 GitHub Actions Docker Distribution

**Defined:** 2026-02-20
**Core Value:** Automate Docker image builds of the custom Dremio OSS fork and push to AWS ECR on release tags.

## v1.2 Requirements

Requirements for this milestone. Each maps to roadmap phases.

### CI Trigger

- [x] **TRIG-01**: GitHub Actions workflow triggers on git tag push matching `v*`
- [x] **TRIG-02**: Tag version extracted with `v` prefix stripped (e.g., `v1.2` → `1.2`)
- [x] **TRIG-03**: Extracted version drives both Maven `-Drevision` and Docker image tag

### Maven Build

- [x] **BILD-01**: Workflow uses `actions/setup-java@v5` with Java 21 (temurin) to satisfy enforcer `[21,22)`
- [x] **BILD-02**: Maven dependency cache enabled via `setup-java` `cache: 'maven'` to avoid 45-90 min cold builds
- [x] **BILD-03**: Maven build uses `./mvnw package -DskipTests -Pdremio.no-lint -pl distribution/server -am -Drevision={version}`
- [x] **BILD-04**: Build produces `distribution/server/target/dremio-community-{version}.tar.gz`

### Docker Image

- [x] **DOCK-01**: Dockerfile adapted from `wget DOWNLOAD_URL` to `COPY` for CI-local tarball
- [x] **DOCK-02**: Multi-stage Dockerfile: extractor stage + runtime stage to prevent tarball layer bloat
- [x] **DOCK-03**: Runtime base image changed to `eclipse-temurin:17-jre-jammy` (Java 17 JRE)
- [x] **DOCK-04**: Docker build context is a staging directory (not full repo) to minimize context size

### ECR Push

- [x] **ECR-01**: AWS credentials configured via `aws-actions/configure-aws-credentials` using IAM access keys from GitHub Secrets
- [x] **ECR-02**: ECR login via `aws-actions/amazon-ecr-login@v2`; registry URL from step output (not hardcoded)
- [x] **ECR-03**: Docker image pushed to private AWS ECR with versioned tag (e.g., `1.2`)
- [x] **ECR-04**: Docker image also tagged `latest` on push

## v2 Requirements

Deferred to future milestone. Tracked but not in current roadmap.

### Enhancements

- **ENH-01**: Docker layer cache via `cache-from: type=gha` for faster repeat builds
- **ENH-02**: Workflow step summary output (`GITHUB_STEP_SUMMARY`) logging pushed image URI
- **ENH-03**: Tag format validation step rejecting non-semver tags
- **ENH-04**: Pre-release tag policy (gate `latest` tag to production releases only)

### Advanced

- **ADV-01**: ARM64 multi-platform Docker builds
- **ADV-02**: Automated smoke test (pull + health check) after push
- **ADV-03**: SBOM / supply chain attestations
- **ADV-04**: Separate CI workflow for PR testing vs release workflow for tags

## Out of Scope

| Feature | Reason |
|---------|--------|
| Multi-platform ARM64 builds | 5-10x slower via QEMU; no stated deployment need |
| Running tests in CI | Tag push implies code is already tested; build-only pipeline |
| Branch-triggered builds | Would pollute ECR with dev images; tag-only trigger |
| ECR layer cache | Storage cost + IAM complexity not justified until baseline proven |
| `docker/metadata-action` | Tag derivation is a one-line shell; action adds unjustified overhead |
| Credential vending fix | Unrelated to CI/CD; tracked as future Iceberg REST Catalog work |
