<objective>
Rewrite distribution/docker/Dockerfile as a multi-stage build that uses COPY instead of wget, with eclipse-temurin:17-jre-jammy as the runtime base.

Purpose: The existing Dockerfile downloads the Dremio tarball via wget from an external URL at build time. For CI-local builds where the tarball is produced by the Maven build step (Phase 9), the Dockerfile must instead COPY a local tarball from the build context. A multi-stage build ensures the tarball archive itself does not persist as a layer in the final image, keeping image size under 1.5GB. The runtime base is upgraded from Java 11 JDK to Java 17 JRE (smaller, production-appropriate).

Output: A rewritten distribution/docker/Dockerfile ready for use in the Phase 11 CI workflow.
</objective>

  <name>Task 1: Rewrite Dockerfile as multi-stage COPY-based build</name>
  <files>distribution/docker/Dockerfile</files>
  <action>
Rewrite distribution/docker/Dockerfile with the following structure. Preserve the Apache 2.0 license header (lines 1-15) exactly as-is.

**Stage 1 — Extractor:**
```
ARG TARBALL_PATH=dremio.tar.gz
FROM busybox AS extractor
ARG TARBALL_PATH
COPY ${TARBALL_PATH} /tmp/dremio.tar.gz
RUN mkdir -p /opt/dremio \
    && tar xzf /tmp/dremio.tar.gz -C /opt/dremio --strip-components=1 \
    && rm /tmp/dremio.tar.gz
```

Key points:
- The first `ARG TARBALL_PATH` is BEFORE any FROM (global scope) so it can be referenced in COPY.
- The second `ARG TARBALL_PATH` is needed inside the extractor stage to inherit the global arg.
- Use `busybox` as the extractor base — minimal image with tar support, discarded after build.
- COPY the tarball from the build context, extract it, then delete the archive. This stage is thrown away so neither the COPY layer nor the archive persists in the final image.

**Stage 2 — Runtime:**
```
ARG JAVA_IMAGE="eclipse-temurin:17-jre-jammy"
FROM ${JAVA_IMAGE} AS runtime

LABEL maintainer=Dremio

RUN \
  mkdir -p /opt/dremio \
  && mkdir -p /var/lib/dremio \
  && mkdir -p /var/run/dremio \
  && mkdir -p /var/log/dremio \
  && mkdir -p /opt/dremio/data \
  \
  && groupadd --system dremio --gid 999 \
  && useradd --base-dir /var/lib/dremio --system --uid 999 --gid dremio dremio \
  && chown -R dremio:dremio /opt/dremio/data \
  && chown -R dremio:dremio /var/run/dremio \
  && chown -R dremio:dremio /var/log/dremio \
  && chown -R dremio:dremio /var/lib/dremio

COPY --from=extractor --chown=dremio:dremio /opt/dremio /opt/dremio

EXPOSE 9047/tcp
EXPOSE 31010/tcp
EXPOSE 32010/tcp
EXPOSE 45678/tcp

USER dremio
WORKDIR /opt/dremio
ENV DREMIO_HOME /opt/dremio
ENV DREMIO_PID_DIR /var/run/dremio
ENV DREMIO_GC_LOGS_ENABLED="yes"
ENV DREMIO_GC_LOG_TO_CONSOLE="yes"
ENV DREMIO_LOG_DIR="/var/log/dremio"
ENTRYPOINT ["bin/dremio", "start-fg"]
```

Key points:
- `ARG JAVA_IMAGE="eclipse-temurin:17-jre-jammy"` keeps the image overridable but defaults to JRE 17 (not JDK 11).
- Stage is named `runtime` (not `base` from the original) for clarity.
- REMOVE: `ARG DOWNLOAD_URL`, `apt-get update`, `apt-get install wget`, `wget`, `tar`, `rm -rf dremio.tar.gz` from the RUN block.
- KEEP: All directory creation, user/group creation (dremio:999), chown commands, all EXPOSE ports, all ENV vars, USER/WORKDIR/ENTRYPOINT.
- `COPY --from=extractor --chown=dremio:dremio /opt/dremio /opt/dremio` brings in the extracted Dremio files with correct ownership. The `--chown` flag ensures files are owned by dremio:dremio without a separate chown layer.
- Do NOT include `apt-get` at all in the runtime stage — wget is no longer needed, and the JRE base image has everything else required.

**What NOT to do:**
- Do NOT use a single-stage build with COPY + RUN tar (creates two large layers: the tarball COPY layer + the extracted layer).
- Do NOT keep `ARG DOWNLOAD_URL` — it is fully replaced by `ARG TARBALL_PATH`.
- Do NOT use `eclipse-temurin:17-jdk-jammy` — use JRE not JDK for the runtime stage.
- Do NOT remove `rm -rf /var/lib/apt/lists/*` and add it back — there is no apt-get in the runtime stage at all.
