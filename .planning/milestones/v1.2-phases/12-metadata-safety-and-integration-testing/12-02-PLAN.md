Three changes to DescribeTableHandler.toResult():

**Change 1: Add soft-deny validatePrivilege(SELECT) call before getTable()**

IMPORTANT: `validatePrivilege(SELECT)` checks VDS grants only (resolveRbacObjectType maps SELECT → "VDS"). For PDS paths where the user has a PDS SELECT grant (from Phase 10), validatePrivilege would incorrectly throw because it only looks up VDS grants. To handle this, use a soft-deny pattern: catch the UserException, save it, proceed to getTable(). If getTable() succeeds (PDS grant allowed it), the table is accessible. If getTable() also returns null, re-throw the saved permission denied.

In the `toResult()` method, INSIDE the try block, as the first statements (before `TableVersionContext sourceVersion = getVersion(...)`), add:

```java
// META-02: Enforce SELECT privilege before table lookup.
// Uses soft-deny: validatePrivilege checks VDS grants only. For PDS paths with
// PDS SELECT grants, getTable() will succeed via isRbacDeniedForPds. We save
// the exception and re-throw only if getTable() also fails.
// Skip for sys/INFORMATION_SCHEMA (system schemas use separate access control).
UserException savedPermissionDenied = null;
if (!"sys".equalsIgnoreCase(path.getRoot())
        && !"INFORMATION_SCHEMA".equalsIgnoreCase(path.getRoot())) {
    try {
        catalog.validatePrivilege(path, SqlGrant.Privilege.SELECT);
    } catch (UserException ue) {
        savedPermissionDenied = ue;
    }
}
```

Then, after `DremioTable table = catalog.getTable(catalogEntityKey)` and before the existing null check that throws "Unknown table", add:

```java
if (table == null) {
    if (savedPermissionDenied != null) {
        throw savedPermissionDenied; // Permission denied takes priority over "Unknown table"
    }
    throw UserException.validationError()
        .message("Unknown table [%s]", path)
        .buildSilently();
}
```

Replace the existing `if (table == null) { throw ... "Unknown table" }` block with the above.

Add the import for `SqlGrant` if not already present:
```java
import com.dremio.exec.planner.sql.parser.SqlGrant;
```

**Why this works for all cases:**
- VDS user WITH SELECT grant: validatePrivilege passes → getTable succeeds → DESCRIBE works
- VDS user WITHOUT SELECT grant: validatePrivilege throws (saved) → getTable returns null (deny-by-null) → re-throw "Permission denied"
- PDS user WITH PDS SELECT grant: validatePrivilege throws (VDS check fails, saved) → getTable succeeds (isRbacDeniedForPds allows) → DESCRIBE works (exception discarded)
- PDS user WITHOUT PDS SELECT grant: validatePrivilege throws (saved) → getTable returns null → re-throw "Permission denied"

**Why skip sys and INFORMATION_SCHEMA:** These are system schemas. `sys.privileges` is already gated by `isRbacDeniedForSysPrivileges()` in getTable(). Other sys tables and INFORMATION_SCHEMA tables are open to all users.

**Change 2: Add UserException catch before the generic Exception catch**

The existing exception handling at lines 151-159 is:
```java
} catch (AccessControlException e) {
    throw UserException.permissionError(e)
        .message("Not authorized to describe table.")
        .build(logger);
} catch (Exception ex) {
    throw UserException.planError(ex)
        .message("Error while rewriting DESCRIBE query: %s", ex.getMessage())
        .build(logger);
}
```

Add a `catch (UserException ue)` block between the AccessControlException catch and the Exception catch:
```java
} catch (AccessControlException e) {
    throw UserException.permissionError(e)
        .message("Not authorized to describe table.")
        .build(logger);
} catch (UserException ue) {
    throw ue; // preserve RBAC permission denied messages (META-02)
} catch (Exception ex) {
    throw UserException.planError(ex)
        .message("Error while rewriting DESCRIBE query: %s", ex.getMessage())
        .build(logger);
}
```

This is CRITICAL (Pitfall 5 from research): without this catch, any UserException that escapes from the try body (e.g., from the `throw savedPermissionDenied` path) would be caught by `catch (Exception ex)` and wrapped as "Error while rewriting DESCRIBE query: Permission denied: ..." instead of the clean "Permission denied: SELECT privilege required on 'path'" message.

The old code after getTable() had:

```java
        .message("Unknown table [%s]", path)

```

This is replaced by the soft-deny version in Change 1 that checks savedPermissionDenied first.
