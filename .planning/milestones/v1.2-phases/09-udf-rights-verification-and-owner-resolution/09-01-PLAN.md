<objective>
Add the `owner` field to FunctionConfig proto, stamp the creator's username at UDF creation time, preserve owner on update, and fix CatalogEntityOwnershipImpl to return the correct owner for FUNCTION type entities.

Purpose: Without this change, UDF definer semantics are broken — `UserDefinedFunctionExpanderImpl.parseAndValidate()` already calls `.withUser(getOwner())` but receives the query user (fallback) instead of the UDF creator, because `getCatalogEntityOwner()` returns `Optional.empty()` for FUNCTION type. This plan fixes the root cause: no owner is stored, so none can be returned.

Output: Three modified files that together enable UDF definer semantics (UDF-01) and correct FUNCTION ownership resolution (UDF-02).
</objective>
