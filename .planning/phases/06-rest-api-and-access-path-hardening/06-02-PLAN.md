**Step 2: Add private filtering methods**

Add two private methods near the bottom of the class (before the inner classes/enums):

```java
/**
 * Filters namespace children by visibility based on RBAC grants.
 * Admin users and RBAC-disabled mode see everything.
 * Non-admin users see only VDS/FUNCTION items they have grants on.
 * Containers (FOLDER, SPACE, SOURCE, HOME) and physical datasets are always visible.
 */
private List<NameSpaceContainer> filterByVisibility(List<NameSpaceContainer> children) {
  if (rbacService == null || dremioConfig == null
      || !dremioConfig.getBoolean(DremioConfig.RBAC_ENABLED)) {
    return children;
  }
  String userName = securityContext.getUserPrincipal().getName();
  if (rbacService.isAdminMember(userName)) {
    return children;
  }
  return children.stream()
      .filter(c -> isVisibleToUser(c, userName))
      .collect(Collectors.toList());
}

private boolean isVisibleToUser(NameSpaceContainer container, String userName) {
  if (container.getType() == NameSpaceContainer.Type.DATASET) {
    DatasetConfig ds = container.getDataset();
    if (ds.getType() == DatasetType.VIRTUAL_DATASET) {
      String objectPath = String.join(".", container.getFullPathList());
      return rbacService.hasPrivilege(userName, "SELECT", "VDS", objectPath);
    }
    // Physical datasets (promoted, PDS) are always visible
    return true;
  }
  if (container.getType() == NameSpaceContainer.Type.FUNCTION) {
    String objectPath = String.join(".", container.getFullPathList());
    return rbacService.hasPrivilege(userName, "EXECUTE", "FUNCTION", objectPath);
  }
  // FOLDER, SPACE, SOURCE, HOME are always visible (containers)
  return true;
}
```

**Step 4: Apply filtering in getTopLevelCatalogItems()**

In `getTopLevelCatalogItems()` (around line 343), the method already lists items individually (home, spaces, sources, functions). The only items that need filtering are functions. Add RBAC filtering for the function loop:

After line `for (FunctionConfig functionConfig : namespaceService.getTopLevelFunctions())`, wrap the add in an RBAC check:

```java
for (FunctionConfig functionConfig : namespaceService.getTopLevelFunctions()) {
  if (rbacService == null || dremioConfig == null
      || !dremioConfig.getBoolean(DremioConfig.RBAC_ENABLED)
      || rbacService.isAdminMember(securityContext.getUserPrincipal().getName())
      || rbacService.hasPrivilege(
          securityContext.getUserPrincipal().getName(),
          "EXECUTE", "FUNCTION",
          String.join(".", functionConfig.getFullPathList()))) {

  }
}
```

Alternatively, for cleaner code, extract a helper `private boolean isFunctionVisibleToUser(FunctionConfig f)` that encapsulates the RBAC check and call it inline.

**Important notes:**
- Do NOT filter physical datasets -- only VIRTUAL_DATASET type (VDS) is access-controlled per locked decision
- Do NOT filter folders/spaces/sources/homes -- they are containers and should remain visible even if all their contents are hidden
- The `String.join(".", container.getFullPathList())` produces the same dot-delimited format used by RbacConfig.grantKey() and CatalogImpl.validatePrivilege() -- this ensures grant keys match between listing and enforcement
- The filterByVisibility approach is simple post-fetch filter. It does NOT attempt to "refill" pages when items are removed. This is a documented v1 limitation.
