3. **Add private helper `explainAnalyze(String sql)`** that:
   - Opens a direct JDBC connection to the PG container (using `PG.getJdbcUrl()`,
     `PG.getUsername()`, `PG.getPassword()`)
   - Executes `EXPLAIN ANALYZE ` + sql
   - Collects all result rows into a single String
   - Returns that String
   ```java
   private static String explainAnalyze(String sql) throws Exception {
     try (Connection conn = DriverManager.getConnection(
             PG.getJdbcUrl(), PG.getUsername(), PG.getPassword());
          Statement stmt = conn.createStatement();
          java.sql.ResultSet rs = stmt.executeQuery("EXPLAIN ANALYZE " + sql)) {
       StringBuilder sb = new StringBuilder();
       while (rs.next()) {
         sb.append(rs.getString(1)).append("\n");
       }
       return sb.toString();
     }
   }
   ```
   Note: the EXPLAIN ANALYZE query is run directly against PG (bypassing Dremio) using the SQL
   that Dremio would push down. The pushed-down SQL can be read from PG logs (pg_new_lines), but
   for EXPLAIN ANALYZE we reconstruct the equivalent native PG query:
   `SELECT * FROM public.embeddings ORDER BY embedding <-> '[0.5,1.0,1.5]' LIMIT 10`
   This is the PG-native form of what Dremio pushes. Document this in the test method Javadoc.
