**CatalogEntityOwnershipImpl.java** — Fix the VIRTUAL_DATASET branch in `getCatalogEntityOwner()`:

Replace the current logic (lines 47-55) that returns `Optional.empty()` for VDS with:

```java
case DATASET:
  {
    final DatasetConfig dataset = nameSpaceContainer.getDataset();
    final String owner = dataset.getOwner();
    if (owner == null || owner.isEmpty()) {
      return Optional.empty(); // Legacy VDS without recorded owner
    }
    return Optional.of(new CatalogUser(owner));
    // Note: PDS and VDS both return the owner now — the VIRTUAL_DATASET
    // early-return that previously discarded the owner is removed.
  }

The null/empty guard handles legacy VDS that were created before owner tracking. When owner is null, `Optional.empty()` propagates as `viewOwner = null` in ViewTable, so ViewExpander keeps the query user's identity (backward-compatible legacy behavior). The `DatasetType` import is no longer needed — remove it if the IDE flags it.
