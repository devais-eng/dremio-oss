Create the proto3 schema and the config-file feature flag -- the two foundational artifacts that all downstream phases depend on.

Purpose: The proto3 messages (Role, Grant, Membership) define the wire format stored in the three KV stores. The feature flag (services.rbac.enabled, defaults OFF) gates RBAC enforcement so the system behaves identically to pre-RBAC Dremio until explicitly enabled. Both artifacts must exist and compile before Phase 2 can write any store code.

Output: `rbac.proto` (compilable proto3 file), `DremioConfig.RBAC_ENABLED` constant, `services.rbac.enabled: false` default in dremio-reference.conf.

  <name>Task 1: Create rbac.proto with Role, Grant, and Membership messages</name>
  <files>sabot/kernel/src/main/protobuf/rbac.proto</files>
  <action>
Create `sabot/kernel/src/main/protobuf/rbac.proto` using proto3 syntax. Model the file header exactly after the established kernel pattern from `vacuum-log.proto` and `query-state.proto`:

```protobuf
syntax = "proto3";

option java_package = "com.dremio.exec.rbac.proto";
option java_outer_classname = "RbacProto";
option optimize_for = SPEED;

package com.dremio.exec.rbac.proto;
```

Then define three messages with these exact fields and field numbers (field numbers are permanent -- treat them as immutable once written):

**Role message:**
- `string role_id = 1;` — slugified role name, immutable identity key
- `string role_name = 2;` — human-readable role name (same value for Phase 1; rename requires DROP+CREATE)
- `string created_by = 3;` — username of creator
- `uint64 created_at = 4;` — epoch millis; matches codebase convention (see script.proto, FunctionRPC.proto)

**Grant message:**
- `string role_id = 1;` — which role holds this grant
- `string object_type = 2;` — stored as plain string: "VDS", "FUNCTION" (NOT a proto enum -- per user decision)
- `string object_path = 3;` — dot-delimited path, e.g. "schemas.my_view"
- `string privilege = 4;` — stored as plain string: "SELECT", "EXECUTE", "CREATE_VIEW" (NOT a proto enum -- per user decision)
- `string granted_by = 5;` — username of granter
- `uint64 granted_at = 6;` — epoch millis

**Membership message:**
- `string user_name = 1;` — username of the member
- `string role_id = 2;` — which role this membership belongs to
- `string granted_by = 3;` — username of granter
- `uint64 granted_at = 4;` — epoch millis

Add a file-level comment block above the messages explaining the key format choices:
```
// KV Store Key Format Specification
//
// oss_rbac_roles   — key: role_id (slugified role name, e.g. "analyst")
// oss_rbac_grants  — key: composite pipe-delimited string:
//                    "{role_id}|{object_type}|{object_path}|{privilege}"
//                    e.g. "analyst|VDS|schemas.my_view|SELECT"
//                    Pipe separator is safe: not present in slugified role IDs,
//                    dot-paths, or privilege names.
//                    Use Format.ofString() -- NOT Format.ofCompoundFormat() --
//                    to preserve human-readable key inspection.
// oss_rbac_memberships — key: composite pipe-delimited string:
//                         "{user_name}|{role_id}"
//                         e.g. "alice|analyst"
//
// ADMIN and PUBLIC are synthetic constants -- never written to any KV store.
// hasPrivilege() checks for them directly in code.
```

Do NOT use `required` fields (proto3 has none). Do NOT use proto enums for privilege or object_type (user decision: stored as strings for forward compatibility).

The `protobuf-maven-plugin` in sabot/kernel/pom.xml automatically compiles all .proto files in `src/main/protobuf/` -- no pom.xml changes are needed.
  </action>
  <verify>
Run `mvn compile -pl sabot/kernel -am -q 2>&1 | tail -20` from the repo root. The build must succeed with no errors mentioning rbac.proto. Alternatively verify the generated Java class appears: `ls sabot/kernel/target/generated-sources/protobuf/java/com/dremio/exec/rbac/proto/RbacProto.java` (path may vary slightly by Maven plugin version -- check for any file containing "RbacProto" under target/).
  </verify>
