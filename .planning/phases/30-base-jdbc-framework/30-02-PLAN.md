  <name>Task 1: Implement JdbcSchemaFetcher and wire SupportsListingDatasets into JdbcStoragePlugin</name>
  <files>
    plugins/jdbc-base/src/main/java/com/dremio/plugins/jdbc/schema/JdbcSchemaFetcher.java

  <action>
1. **JdbcSchemaFetcher.java** — Encapsulates all DatabaseMetaData interactions:
   - Constructor takes `JdbcConnectionPool pool`
   - **`listSchemas()`**: Calls `DatabaseMetaData.getSchemas()` via a pooled connection. Returns `List<String>` of schema names. Filters out system schemas like `information_schema`, `pg_catalog` (configurable via a protected method `isSystemSchema(String)` that concrete connectors can override).
   - **`listTables(String schemaName)`**: Calls `DatabaseMetaData.getTables(null, schemaName, "%", new String[]{"TABLE", "VIEW"})`. Returns list of table name strings.
   - **`getTableSchema(String schemaName, String tableName)`**: Calls `DatabaseMetaData.getColumns(null, schemaName, tableName, "%")`. For each column:
     - Get `COLUMN_NAME`, `DATA_TYPE` (java.sql.Types constant), `TYPE_NAME`, `COLUMN_SIZE`, `DECIMAL_DIGITS`, `IS_NULLABLE`
     - Use `arrow-jdbc`'s `JdbcToArrowUtils.getArrowTypeForJdbcType()` to convert JDBC type → Arrow type (this handles BASE-03 type mapping)
     - Build Arrow `Field` objects (name + ArrowType + nullable)
     - Return `BatchSchema` (Dremio's wrapper around Arrow Schema)
   - All methods acquire a connection from pool, use it within try-with-resources, and release back to pool
   - Provide protected hook method `mapJdbcType(int jdbcType, String typeName, int precision, int scale)` that returns `ArrowType` — default uses `JdbcToArrowUtils` but concrete connectors can override for database-specific types

2. **JdbcStoragePlugin.java** — Update to implement `SupportsListingDatasets`:
   - Add `implements SupportsListingDatasets` to class declaration
   - Add field: `JdbcSchemaFetcher schemaFetcher`
   - In `start()`: create `schemaFetcher = new JdbcSchemaFetcher(pool)` after pool creation
   - Implement `listDatasetHandles(GetDatasetOption... options)`:
     - Use schemaFetcher to iterate schemas and tables
     - For each schema.table pair, create a `DatasetHandle` (use `EntityPath` with 2 components: schema name and table name)
     - Return an `DatasetHandleListing` wrapping the iterator
   - Implement `getDatasetMetadata(DatasetHandle handle, PartitionChunkListing chunkListing, GetMetadataOption... options)`:
     - Extract schema and table name from handle's EntityPath
     - Call `schemaFetcher.getTableSchema(schema, table)` to get `BatchSchema`
     - Return `DatasetMetadata` with the schema
   - Implement `getDatasetHandle(EntityPath entityPath, GetDatasetOption... options)`:
     - Verify the table exists via schemaFetcher
     - Return Optional of DatasetHandle
   - Implement `listPartitionChunks(DatasetHandle handle, PartitionListOption... options)`:
     - JDBC tables are single-partition — return a single `PartitionChunk` containing the full table
   - Reference the `SupportsListingDatasets` interface and `ElasticsearchStoragePlugin` for the exact method signatures
  </action>

1. **JdbcSubScan.java** — Extends `AbstractSubScan`:
   - Carries the query context from planner to executor:
     - `String sql` — the fully constructed SELECT statement (will include pushdown clauses when added in plan 03)
     - `BatchSchema fullSchema` — full table schema
     - `List<SchemaPath> columns` — projected columns (null = all)
     - `StoragePluginId pluginId` — reference to the JDBC storage plugin
   - Serialization: Use `@JsonCreator` constructor + `@JsonProperty` on each field + `@JsonTypeName("jdbc-sub-scan")`
   - `getOperatorType()` returns `CoreOperatorType.JDBC_SUB_SCAN_VALUE` (value 47 — already exists in UserBitShared.proto)
   - Reference `InfoSchemaSubScan.java` and `ElasticsearchSubScan.java` for the exact pattern

2. **JdbcGroupScan.java** — Extends `AbstractGroupScan`:
   - Constructor takes: `OpProps props`, `String sql`, `List<SchemaPath> columns`, `BatchSchema schema`, `StoragePluginId pluginId`
   - `getMaxParallelizationWidth()` returns `1` (JDBC is single-node, prevents LIMIT pushdown issues)
   - `getSpecificScan(List<CoordinationProtos.NodeEndpoint> endpoints, int shard)` returns a new `JdbcSubScan` with the SQL, schema, columns, and pluginId
   - `getDistributionAffinity()` returns `DistributionAffinity.SOFT`
   - Reference `InfoSchemaGroupScan.java` for the pattern (very simple — single shard, single node)

3. **JdbcRecordReader.java** — Extends `AbstractRecordReader`:
   - Constructor takes: `OperatorContext context`, `JdbcSubScan config`, `JdbcConnectionPool pool`
   - Instance fields: `Connection conn`, `PreparedStatement stmt`, `ResultSet rs`, `Map<String, ValueVector> vectors`
   - **`setup(OutputMutator output)`**:
     - Determine projected columns from `config.getColumns()` (or all columns from `config.getFullSchema()`)
     - For each projected column, get the Arrow `Field` from the schema, register the vector via `output.addField(field, vectorClass)` — use `TypeHelper.getValueVectorClass(field)` to resolve vector class
     - Acquire a connection from pool: `conn = pool.getConnection()`
     - Create prepared statement: `stmt = conn.prepareStatement(config.getSql())` with `ResultSet.TYPE_FORWARD_ONLY` and `ResultSet.CONCUR_READ_ONLY`
     - Set fetch size: `stmt.setFetchSize(numRowsPerBatch)` to avoid OOM on large tables
     - Execute: `rs = stmt.executeQuery()`
   - **`next()`**:
     - Loop up to `numRowsPerBatch` rows:
       - Call `rs.next()` — if false, return count
       - For each projected column/vector, read from ResultSet and write to the appropriate ValueVector
       - Use a `writeValue(ValueVector vec, ResultSet rs, String colName, int index)` helper method that dispatches on vector type:
         - `IntVector` → `rs.getInt()`, `BigIntVector` → `rs.getLong()`, `VarCharVector` → `rs.getString().getBytes(UTF_8)`, `Float4Vector` → `rs.getFloat()`, `Float8Vector` → `rs.getDouble()`, `BitVector` → `rs.getBoolean()`, `DateMilliVector` → date millis, `TimeMilliVector` → time millis, `TimeStampMilliVector` → timestamp millis, `DecimalVector` → `rs.getBigDecimal()`, `VarBinaryVector` → `rs.getBytes()`
         - Check `rs.wasNull()` after each get — if null, don't set the vector value (it defaults to null)
       - Increment count
     - After loop: set value count on all vectors
     - Return count
   - **`close()`**: Close `rs`, `stmt`, `conn` in reverse order within try-catch (swallow close exceptions, log them)
   - The `writeValue` helper should be a protected method so concrete connectors can override it for database-specific types

4. **JdbcScanCreator.java** — Implements `ProducerOperator.Creator<JdbcSubScan>`:
   - `create(FragmentExecutionContext fec, OperatorContext context, JdbcSubScan config)`:
     - Get plugin: `JdbcStoragePlugin plugin = fec.getStoragePlugin(config.getPluginId())`
     - Create reader: `JdbcRecordReader reader = new JdbcRecordReader(context, config, plugin.getPool())`
     - Return: `new ScanOperator(fec, config, context, RecordReaderIterator.from(reader))`
   - Reference `InfoSchemaScanCreator.java` for the exact pattern
  </action>
