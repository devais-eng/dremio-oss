1. **SqlBuilder.java** — Utility class that constructs SQL strings:
   - Static method `buildSql(String schemaName, String tableName, List<SchemaPath> projectedColumns, String whereClause, Integer limit)`:
     - If `projectedColumns` is null or empty: `SELECT *`
     - Else: `SELECT "col1", "col2", ...` (double-quote column names for identifier safety)
     - `FROM "schemaName"."tableName"` (double-quoted identifiers)
     - If `whereClause` is not null: append `WHERE whereClause`
     - If `limit` is not null: append `LIMIT limit`
     - Return the complete SQL string
   - Protected method so concrete connectors can override SQL dialect (e.g., Oracle uses `FETCH FIRST n ROWS ONLY` instead of `LIMIT`)
   - Provide a `quoteIdentifier(String id)` helper that wraps in double quotes and escapes internal double quotes (SQL standard)

2. **JdbcScanDrel.java** — Logical scan node:
   - Extends the appropriate Dremio logical rel base class (reference `InfoSchemaDrel.java` or similar pattern)
   - Holds: table metadata, schema name, table name
   - This is the logical representation before physical planning
   - Keep it simple — just the container for table identity; pushdown happens at the Prel level

3. **JdbcScanPrel.java** — Physical scan node extending `ScanPrelBase`:
   - Additional fields beyond ScanPrelBase:
     - `String schemaName` — the source schema
     - `String tableName` — the source table
     - `String whereClause` — pushed-down filter (null = no filter)
     - `Integer limit` — pushed-down limit (null = no limit)
     - `StoragePluginId pluginId`
   - **`cloneWithProject(List<SchemaPath> projection)`**: Return new JdbcScanPrel with same filter/limit but updated projected columns. This is how BASE-06 projection pushdown works.
   - **`cloneWithFilter(String newWhereClause)`**: Return new JdbcScanPrel with updated WHERE clause, preserving projection and limit.
   - **`cloneWithLimit(int newLimit)`**: Return new JdbcScanPrel with updated limit, preserving filter and projection.
   - **`getPhysicalOperator(PhysicalPlanCreator creator)`**:
     - Call `SqlBuilder.buildSql(schemaName, tableName, getProjectedColumns(), whereClause, limit)` to construct the final SQL
     - Create and return `new JdbcGroupScan(props, sql, getProjectedColumns(), getTableMetadata().getSchema(), pluginId)`
   - `getMaxParallelizationWidth()` returns `1` (single-node JDBC)
   - `copy(RelTraitSet, List<RelNode>)` — required by Calcite; return clone with new traitSet
   - Reference `InfoSchemaScanPrel.java` for the exact `ScanPrelBase` method signatures

4. **JdbcScanDrule.java** — Converts logical Drel to physical Prel:
   - Matches `JdbcScanDrel` and produces `JdbcScanPrel`
   - Reference `InfoSchemaDrule.java` for the pattern — it's a simple one-method rule

1. **JdbcPushFilterIntoScan.java** — WHERE pushdown rule (BASE-05):
   - Extends `RelOptRule`
   - Singleton: `public static final RelOptRule INSTANCE = ...`
   - Pattern: matches `FilterPrel` above `JdbcScanPrel` using `RelOptHelper.some(FilterPrel.class, RelOptHelper.any(JdbcScanPrel.class))`
   - **`onMatch(RelOptRuleCall call)`**:
     - Extract `FilterPrel filter = call.rel(0)` and `JdbcScanPrel scan = call.rel(1)`
     - Convert `filter.getCondition()` (a `RexNode`) to a SQL WHERE clause string
     - For v1.5, implement a simple `RexNode` → SQL converter that handles:
       - `RexCall` with operators: `=`, `<>`, `<`, `<=`, `>`, `>=`, `AND`, `OR`, `NOT`, `IS NULL`, `IS NOT NULL`
       - `RexInputRef` → column name from scan's row type
       - `RexLiteral` → SQL literal (string in single quotes, numbers as-is, booleans as TRUE/FALSE)
       - `LIKE` operator
     - If any unsupported RexNode component is encountered, do NOT push down (return without calling `call.transformTo`) — let Dremio handle it in-engine
     - If successful: `call.transformTo(scan.cloneWithFilter(whereClause))`
   - Reference `InfoSchemaPushFilterIntoScan.java` for the rule structure
   - Create a helper method or inner class `RexToSqlString` for the conversion

2. **JdbcPushProjectIntoScan.java** — Column projection pushdown (BASE-06):
   - Extends `RelOptRule`
   - Pattern: matches `ProjectPrel` above `JdbcScanPrel`
   - **`onMatch(RelOptRuleCall call)`**:
     - Extract `ProjectPrel project = call.rel(0)` and `JdbcScanPrel scan = call.rel(1)`
     - Extract projected column references from `project.getProjects()` — each `RexInputRef` maps to a column name
     - If all projects are simple column references (no expressions): push down via `scan.cloneWithProject(projectedColumns)`
     - If any project is an expression (not a simple `RexInputRef`): do NOT push down
     - Call `call.transformTo(newScan)` — the ProjectPrel above will be eliminated by Calcite if all columns are covered
   - This is simpler than filter pushdown — just extract column indices and map to names

3. **JdbcPushLimitIntoScan.java** — LIMIT pushdown (BASE-07):
   - Extends `RelOptRule`
   - Pattern: matches `LimitPrel` above `JdbcScanPrel`
   - **`onMatch(RelOptRuleCall call)`**:
     - Extract `LimitPrel limit = call.rel(0)` and `JdbcScanPrel scan = call.rel(1)`
     - Get the fetch count from `limit.getFetch()` — it's a `RexLiteral` representing the LIMIT value
     - Convert to int: `RexLiteral.intValue(limit.getFetch())`
     - If scan already has a limit, take the minimum
     - If scan's `getMaxParallelizationWidth()` is 1 (which it always is for JDBC): safe to push
     - `call.transformTo(scan.cloneWithLimit(fetchCount))`
   - Reference `ElasticsearchLimit.java` for the LimitPrel matching pattern

4. **JdbcRulesFactory.java** — `StoragePluginRulesFactory` implementation:
   - Override `getRules(OptimizerRulesContext context, PlannerPhase phase, SourceType sourceType)`:
     - Only return rules for `PlannerPhase.PHYSICAL` (pushdown operates on physical rels)
     - Return `ImmutableSet.of(JdbcPushFilterIntoScan.INSTANCE, JdbcPushProjectIntoScan.INSTANCE, JdbcPushLimitIntoScan.INSTANCE, JdbcScanDrule.INSTANCE)`
     - For other phases: return empty set
   - Also wire the `JdbcScanDrule` into the factory's logical-to-physical conversion rules
   - Reference `ElasticRulesFactory.java` for the exact pattern of returning rules per phase
   - The factory is resolved by the StoragePlugin via `getRulesFactoryClass()` method — add `getRulesFactoryClass()` returning `JdbcRulesFactory.class` to `BaseJdbcConf` or `JdbcStoragePlugin` (check which class needs it by looking at how Elasticsearch does it)
