<objective>
Implement ORDER BY and TopN (ORDER BY + LIMIT combined) pushdown for JDBC sources.

Purpose: Reduce data transfer by pushing sort operations to the source database. When a user query includes ORDER BY (and optionally LIMIT), the JDBC source generates sorted SQL directly, avoiding a full table scan followed by in-engine sorting. TopN is the combination of ORDER BY + LIMIT, which is especially efficient for "top N rows" queries.

Output: JdbcPushSortIntoScan rule, JdbcScanPrel with orderByClause field, SqlBuilder/OracleSqlBuilder with ORDER BY clause generation, integration tests for both PG and Oracle.
</objective>

    **2. Create `JdbcPushSortIntoScan.java`** in `com.dremio.plugins.jdbc.planning`:
    - Extends `RelOptRule`.
    - `INSTANCE` static singleton.
    - Constructor: `RelOptHelper.some(SortPrel.class, RelOptHelper.any(JdbcScanPrel.class))`, name `"JdbcPushSortIntoScan"`.
    - Import `com.dremio.exec.planner.physical.SortPrel`.
    - Import `org.apache.calcite.rel.RelCollation`, `org.apache.calcite.rel.RelFieldCollation`.
    - `matches()`:
      - `JdbcScanPrel scan = call.rel(1)` — reject if scan already has ORDER BY (`scan.hasOrderBy()`).
      - `SortPrel sort = call.rel(0)` — reject if sort has a non-null offset (offset not expressible in ORDER BY alone).
      - Check `sort.getCollation().getFieldCollations()` is non-empty.
    - `onMatch()`:
      - Extract `SortPrel sort = call.rel(0)` and `JdbcScanPrel scan = call.rel(1)`.
      - Call `collationToSql(sort.getCollation(), scan.getRowType())` to produce the ORDER BY clause string.
      - If result is null (unsupported direction like CLUSTERED), return without transformation.
      - **TopN mechanism:** The primary TopN path is sequential rule firing — JdbcPushSortIntoScan fires first to absorb ORDER BY into the scan, then the existing JdbcPushLimitIntoScan fires to absorb LIMIT. SqlBuilder combines both in the correct SQL order. As a secondary path, if SortPrel itself carries a fetch (check `sort.getFetch()` inherited from Calcite's Sort), clone with both orderBy and limit in a single step.
      - Otherwise: `call.transformTo(scan.cloneWithOrderBy(orderByClause))`.
    - Private method `collationToSql(RelCollation collation, RelDataType rowType)`:
      - Iterate `collation.getFieldCollations()`.
      - For each `RelFieldCollation fc`:
        - Get field index, validate within rowType bounds. If out of bounds, return null.
        - Quote the field name using double-quote escaping (same pattern as RexToSqlString).
        - Direction: `ASCENDING` / `STRICTLY_ASCENDING` -> ` ASC`, `DESCENDING` / `STRICTLY_DESCENDING` -> ` DESC`, anything else (CLUSTERED) -> return null.
        - Null direction: `FIRST` -> ` NULLS FIRST`, `LAST` -> ` NULLS LAST`, `UNSPECIFIED` -> omit (let database use its default). Access via `fc.nullDirection` field (public in Calcite 1.22).
      - Comma-separate multiple sort columns.
      - Return the full ORDER BY expression string (WITHOUT the "ORDER BY" keyword — SqlBuilder adds that).

    - Update Javadoc to document the new rule.
