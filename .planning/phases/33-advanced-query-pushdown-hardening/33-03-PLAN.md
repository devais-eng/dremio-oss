<objective>
Implement aggregation pushdown (GROUP BY + COUNT/SUM/MIN/MAX/AVG) for JDBC sources.

Purpose: Push aggregate operations to the source database, dramatically reducing data transfer for analytic queries. Instead of transferring millions of rows and aggregating in Dremio, the source database performs the GROUP BY + aggregation and returns only the summarized result set.

Output: JdbcPushAggIntoScan rule, JdbcScanPrel with aggregation state (selectExprs, groupByClause, updated rowType), integration tests for both PG and Oracle verifying correct aggregate SQL generation and result correctness.
</objective>

    **1. Update `JdbcScanPrel.java`** — add aggregation state:
    - Add fields:
      - `private final List<String> selectExprs;` (nullable — when non-null, replaces projectedColumns in SELECT list; contains items like `"name"`, `COUNT(*)`, `SUM("amount")`)
      - `private final String groupByClause;` (nullable — e.g., `"name", "category"`)
    - Update constructor to accept both new fields (after orderByClause).
    - Add `cloneWithAggregation(List<String> newSelectExprs, String newGroupByClause, RelDataType newRowType)`:
      - Creates a new JdbcScanPrel with the aggregation state.
      - **CRITICAL:** This clone must use the `newRowType` to create a scan with a different output schema. The standard ScanPrelBase constructor derives rowType from the TableMetadata dataset, so this requires overriding `deriveRowType()` or passing the new rowType through a different mechanism.
      - Approach: Store an optional `RelDataType overrideRowType` field. When non-null, `getRowType()` returns this instead of the base class derivation. Add the override field to the constructor.
      - When aggregation is set, `projectedColumns` should be set to null (SELECT list comes from selectExprs, not from projectedColumns).
    - Add accessors: `getSelectExprs()`, `getGroupByClause()`, `hasAggregation()`.
    - Update ALL existing clone helpers to pass through `selectExprs`, `groupByClause`, and the override rowType.
    - Update `explainTerms()`: add items for selectExprs and groupByClause.
    - Update `getPhysicalOperator()`:
      - Include `.selectExprs(selectExprs).groupBy(groupByClause)` in the `SqlBuildRequest` builder.
      - **CRITICAL RowType for schema:** When aggregation is active, the `BatchSchema` passed to `JdbcGroupScan` must reflect the aggregated output schema, not the original table schema. Use the override rowType to derive a `BatchSchema` for the aggregated columns. Convert `RelDataType` to `BatchSchema` using `CalciteArrowHelper.fromCalciteRowType(overrideRowType)` or by manually constructing Arrow Field list from the RelDataType fields.
      - When aggregation is set, the `maskAndReorder` call for projectedColumns should be skipped — use the full aggregated schema directly.

    **2. Create `JdbcPushAggIntoScan.java`** in `com.dremio.plugins.jdbc.planning`:
    - Extends `RelOptRule`.
    - `INSTANCE` static singleton.
    - Constructor pattern matches `AggregatePrel(JdbcScanPrel)`:
      - Use `RelOptHelper.some(AggregatePrel.class, RelOptHelper.any(JdbcScanPrel.class))`.
      - Name: `"JdbcPushAggIntoScan"`.
      - Import `com.dremio.exec.planner.physical.AggregatePrel` (the base class that both HashAggPrel and StreamAggPrel extend). Matching on the base class catches both.
    - `matches(RelOptRuleCall call)`:
      - `AggregatePrel agg = call.rel(0)`.
      - **CRITICAL phase check:** `agg.getOperatorPhase() == AggregatePrel.OperatorPhase.PHASE_1of1`. Reject PHASE_1of2 and PHASE_2of2 — these are partial/final aggregates in 2-phase distributed plans. Only single-phase aggregates are correct to push to a single JDBC source (see research Pitfall 3).
      - Reject if scan already has aggregation (`scan.hasAggregation()`).
      - Reject if any `AggregateCall` has `isDistinct() == true` — DISTINCT aggregates are not pushed down in v1 (see research Open Question 3).
      - Reject if any `AggregateCall` has an unsupported function (anything other than COUNT, SUM, SUM0, MIN, MAX, AVG).
    - `onMatch(RelOptRuleCall call)`:
      - `AggregatePrel agg = call.rel(0)`.
      - `JdbcScanPrel scan = call.rel(1)`.
      - Extract `ImmutableBitSet groupSet = agg.getGroupSet()`.
      - Extract `List<AggregateCall> aggCalls = agg.getAggCallList()`.
      - Get `RelDataType scanRowType = scan.getRowType()` and its field list.
      - **Build GROUP BY column list:**
        - For each index in `groupSet`: get the field name from scanRowType, quote it with double-quote escaping. If index out of bounds, return (decline).
        - Join with ", " to form groupByClause.
      - **Build SELECT expressions list:**
        - Start with the group-by column expressions (quoted field names).
        - For each `AggregateCall`:
          - Call `aggCallToSql(call, scanRowType.getFieldList())`.
          - If null (unsupported), return (decline).
          - Add to selectExprs list.
      - **Build new rowType:**
        - The output rowType must match what Calcite expects from the AggregatePrel.
        - Use `agg.getRowType()` as the new rowType — this is the aggregated output type that Calcite already computed. The JdbcScanPrel must produce this exact type.
      - Call `scan.cloneWithAggregation(selectExprs, groupByClause, agg.getRowType())`.
      - `call.transformTo(newScan)`.

    - Private helper `aggCallToSql(AggregateCall call, List<RelDataTypeField> fields)`:
      - Switch on `call.getAggregation().getKind()`:
        - `SqlKind.COUNT`:
          - If `call.getArgList().isEmpty()`: return `"COUNT(*)"`.
          - Else: return `"COUNT(" + quoteField(fields.get(call.getArgList().get(0))) + ")"`.
        - `SqlKind.SUM` / `SqlKind.SUM0`:
          - Return `"SUM(" + quoteField(fields.get(call.getArgList().get(0))) + ")"`.
        - `SqlKind.MIN`:
          - Return `"MIN(" + quoteField(fields.get(call.getArgList().get(0))) + ")"`.
        - `SqlKind.MAX`:
          - Return `"MAX(" + quoteField(fields.get(call.getArgList().get(0))) + ")"`.
        - `SqlKind.AVG`:
          - Return `"AVG(" + quoteField(fields.get(call.getArgList().get(0))) + ")"`.
        - Default: return null (unsupported aggregate function — decline pushdown).
      - Validate arg index bounds before field access.
    - Private helper `quoteField(RelDataTypeField field)`:
      - `return "\"" + field.getName().replace("\"", "\"\"") + "\""`.

    **3. Update `JdbcRulesFactory.java`**:

    - Aggregation pushdown is NOT registered in PHYSICAL_HEP — aggregation is a structural transformation (changes rowType) that should happen in Volcano where cost-based decisions are made.
    - Update Javadoc.
