    **1. Create `BindParam.java`** in `com.dremio.plugins.jdbc.planning`:
    - Immutable class with `@JsonCreator` / `@JsonProperty` for JSON serialization through the operator chain.
    - Fields: `Object value` (boxed Java type: Integer, Long, Double, String, Boolean, BigDecimal, or null), `SqlTypeName typeName` (the Calcite type for dispatch to stmt.setXxx()).
    - Constructor: `BindParam(Object value, SqlTypeName typeName)`.
    - Getters: `getValue()`, `getTypeName()`.
    - `SqlTypeName` serializes as a string via Jackson by default (it's an enum).
    - **IMPORTANT:** `value` must be a standard JSON-safe type. For DATE/TIME/TIMESTAMP literals, store as ISO string and convert back in JdbcRecordReader. For most filter literals (numbers, strings, booleans), boxed Java types serialize naturally.

    **2. Create `RexToSqlResult.java`** in `com.dremio.plugins.jdbc.planning`:
    - Immutable class.
    - Fields: `String sql` (the WHERE expression with `?` placeholders), `List<BindParam> params` (ordered list of bind values, one per `?`).
    - Constructor: `RexToSqlResult(String sql, List<BindParam> params)`.
    - Static factory: `RexToSqlResult.literal(String sql)` for non-parameterized fragments (returns empty params).
    - Static factory: `RexToSqlResult.param(BindParam param)` for single `?` with one param.
    - `merge(RexToSqlResult other, String separator)` method that concatenates sql with separator and appends params lists.

    **3. Create `RexToSqlString.java`** as a top-level class in `com.dremio.plugins.jdbc.planning`:
    - EXTRACT from the inner class `RexToSqlString` in `JdbcPushFilterIntoScan.java`.
    - Change the return type of `convert(RexNode)` from `String` to `RexToSqlResult`. Returns null if unsupported.
    - **convertLiteral changes:** Instead of inlining literal values, emit `?` and collect a `BindParam`. Exception: `NULL` literal stays as inline `"NULL"` (not parameterizable). Boolean literals `TRUE`/`FALSE` also stay inline (standard SQL keywords, not injection risk).
    - Numeric literals (TINYINT through DECIMAL): emit `?`, add `BindParam(bigDecimalValue, typeName)`.
    - String literals (CHAR, VARCHAR): emit `?`, add `BindParam(stringValue, typeName)`.
    - Date/Time/Timestamp literals: emit `?`, add `BindParam` with the value as `java.sql.Date`/`java.sql.Time`/`java.sql.Timestamp` (these are JSON-serializable as epoch millis via Jackson, and stmt.setDate/setTime/setTimestamp accepts them directly).
    - **convertCall additions** — add these cases to the existing switch:
      - `PLUS`: `binaryOp(operands, "+")` — merges RexToSqlResult from both sides.
      - `MINUS`: `binaryOp(operands, "-")`.
      - `TIMES`: `binaryOp(operands, "*")`.
      - `DIVIDE`: `binaryOp(operands, "/")`.
      - `IN`: Safety net — handle `SqlKind.IN` if Calcite preserves it. Convert first operand (column), then each subsequent operand (values), combine as `col IN (?, ?, ?)`.
      - `BETWEEN`: 3 operands — `col BETWEEN ? AND ?`. Note: Calcite may represent BETWEEN as `AND(>=, <=)` so this is a safety net.
      - `COALESCE`: N-ary — `COALESCE(expr1, expr2, ...)`.
      - `NULLIF`: Binary — `NULLIF(expr1, expr2)`.
    - **OR-of-EQUALS to IN detection** in the OR case: Before falling back to standard OR handling, call `tryConvertToIn(operands)`. This method checks if ALL operands are EQUALS calls where one side is a RexInputRef referencing the SAME column index. If so, reconstruct as `"col" IN (?, ?, ...)` with collected bind params. If not all match, fall through to standard OR.
    - All existing operators (=, <>, <, <=, >, >=, LIKE, AND, OR, NOT, IS NULL, IS NOT NULL) must continue to work, but `binaryOp` and `nAryOp` now produce `RexToSqlResult` (merging params from sub-expressions).

    **4. Create `SqlBuildRequest.java`** in `com.dremio.plugins.jdbc.planning`:
    - Builder-pattern DTO with fields:
      - `String schemaName` (required)
      - `String tableName` (required)
      - `List<SchemaPath> projectedColumns` (nullable — null means SELECT *)
      - `List<String> selectExprs` (nullable — used for aggregation pushdown in Plan 03; when non-null, replaces projectedColumns in SELECT list)
      - `String whereClause` (nullable)
      - `List<BindParam> bindParams` (nullable — bind params for WHERE clause ?)
      - `String groupByClause` (nullable — for Plan 03)
      - `String orderByClause` (nullable — for Plan 02)
      - `Integer limit` (nullable)
    - Static inner `Builder` class with `schema()`, `table()`, `projectedColumns()`, `selectExprs()`, `where()`, `bindParams()`, `groupBy()`, `orderBy()`, `limit()` setters.
    - `build()` validates schemaName and tableName are non-null.

    **5. Refactor `SqlBuilder.java`**:
    - Add new method: `public String buildSql(SqlBuildRequest request)` that extracts fields from the DTO and assembles SQL in the order: SELECT ... FROM ... WHERE ... GROUP BY ... ORDER BY ... LIMIT N.
    - GROUP BY and ORDER BY are emitted between WHERE and LIMIT when non-null.
    - Keep the existing `buildSql(String, String, List<SchemaPath>, String, Integer)` method as a backward-compatible delegate that creates a `SqlBuildRequest` and calls the new method.
    - The SELECT list logic: if `request.getSelectExprs() != null`, join them with commas (used for aggregation); otherwise use projectedColumns as before.

    **6. Refactor `OracleSqlBuilder.java`**:
    - Override `buildSql(SqlBuildRequest request)` instead of (or in addition to) the old 5-parameter signature.
    - Same logic but uses `FETCH FIRST N ROWS ONLY` instead of `LIMIT N`.
    - ORDER BY emitted before FETCH FIRST (correct Oracle syntax per research Pitfall 6).
    - Keep backward-compatible delegate for the old signature.

    **7. Update `JdbcPushFilterIntoScan.java`**:
    - Remove the inner `RexToSqlString` class entirely.
    - Import the new top-level `RexToSqlString` and `RexToSqlResult`.
    - In `onMatch()`: call `new RexToSqlString(scan.getRowType()).convert(filter.getCondition())` which now returns `RexToSqlResult`.
    - If result is null, return (unchanged behavior).
    - Call `scan.cloneWithFilter(result.getSql(), result.getParams())` (new signature — see Task 2).
