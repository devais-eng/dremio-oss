<objective>
Enable pgvector HNSW index-accelerated nearest-neighbor search by translating Dremio distance function calls to pgvector infix operators at SQL rendering time, and by whitelisting the functions so the existing expression-pushdown rules approve ORDER BY distance LIMIT K for pushdown.

Purpose: Without this phase, `ORDER BY l2_distance(embedding, ARRAY[...]) LIMIT K` either stays in Dremio's engine (expensive full-table fetch + in-memory sort) or renders as `ORDER BY l2_distance("embedding", ARRAY[1,2,3]) LIMIT K` which pgvector does not understand. With this phase, the query becomes `ORDER BY "embedding" <-> '[1.0,2.0,3.0]' LIMIT K`, which pgvector can satisfy with an HNSW index scan in O(log N) rather than O(N).

Output: `DremioPostgresDialect.java` (new), modified `StandardPushdownFunctionRegistry.java`, modified `PostgresConf.java`, `TestDremioPostgresDialect.java` (new), modified `TestPostgresPushdown.java`.
</objective>

Key implementation decisions (from RESEARCH.md):

1. **Class declaration**: `public final class DremioPostgresDialect extends PostgresqlSqlDialect` with a `public static final DremioPostgresDialect INSTANCE` singleton constructed via `new DremioPostgresDialect(PostgresqlSqlDialect.DEFAULT_CONTEXT)`.

If `getPgvectorOp` returns null, delegate to `super.unparseCall()`. Otherwise:
   - `SqlWriter.Frame frame = writer.startList(SqlWriter.FrameTypeEnum.SIMPLE, "", "");`

   - `renderVectorOperand(writer, call.operand(1), leftPrec, rightPrec);`
