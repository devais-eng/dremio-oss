    **TestPostgresPushdown.java** — Pushdown SQL verification tests:

    These tests verify that the `SqlBuilder` from the Phase 30 base correctly generates WHERE, projected columns, and LIMIT clauses for PostgreSQL queries. They do NOT need the full Dremio engine — they test the `SqlBuilder` directly.

    The `SqlBuilder` API is: `buildSql(String schemaName, String tableName, List<SchemaPath> projectedColumns, String whereClause, Integer limit)`. It returns a SQL string. `SchemaPath` is from `com.dremio.common.expression.SchemaPath`; create instances via `SchemaPath.getSimplePath("colName")`.

    Tests (using JUnit 4):

    - **Test: testSelectAllColumns** — Call `new SqlBuilder().buildSql("public", "test_table", null, null, null)`. Verify output is `SELECT * FROM "public"."test_table"` (double-quoted identifiers).

    - **Test: testSelectProjectedColumns** — Call `buildSql("public", "test_table", Arrays.asList(SchemaPath.getSimplePath("id"), SchemaPath.getSimplePath("name")), null, null)`. Verify output is `SELECT "id", "name" FROM "public"."test_table"`.

    - **Test: testSelectWithWhereClause** — Call `buildSql("public", "test_table", null, "\"id\" = 1", null)`. Verify output contains `WHERE "id" = 1`.

    - **Test: testSelectWithLimit** — Call `buildSql("public", "test_table", null, null, 100)`. Verify output contains `LIMIT 100`.

    - **Test: testSelectWithWhereAndLimit** — Call `buildSql("public", "test_table", null, "\"id\" > 5", 100)`. Verify output contains both `WHERE` and `LIMIT`.

    - **Test: testSelectWithProjectionAndFilter** — Call `buildSql("public", "test_table", projectedColumns, "\"name\" = 'foo'", null)`. Verify output has the correct column list and WHERE clause.

    - **Test: testSpecialCharactersInIdentifiers** — Call `buildSql("public", "my-table", null, null, null)`. Verify double-quoting handles it correctly: `FROM "public"."my-table"`.

    Additionally, if the container is available, test against real PostgreSQL to verify the generated SQL is valid:

    - **Test: testPushdownQueryExecutesAgainstPostgres** — Create a test table in the container, build SQL using SqlBuilder, execute the SQL via raw JDBC against the container, verify results are returned. This validates that the generated SQL syntax is valid PostgreSQL.

    - **Test: testFilterPushdownResultCorrectness** — Insert multiple rows, build SQL with a WHERE filter, execute against PG, verify only matching rows are returned.

    - **Test: testLimitPushdownResultCorrectness** — Insert multiple rows, build SQL with LIMIT, execute against PG, verify row count matches limit.

    Use `@ClassRule` referencing `PostgresTestContainer.PG` for container-based tests.
  </action>
