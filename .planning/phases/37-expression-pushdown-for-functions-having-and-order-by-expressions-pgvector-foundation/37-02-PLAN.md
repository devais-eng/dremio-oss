    **JdbcPushTopNWithExpressionsHep.java -- new HEP-phase rule for ORDER BY expr + LIMIT K:**

    CRITICAL CONTEXT: Dremio's `PushLimitToTopN` rule fires during the PHYSICAL (Volcano) phase
    and converts `LimitPrel(SingleMergeExchangePrel(SortPrel))` into `TopNPrel`. This means by
    the time PHYSICAL_HEP runs, the plan tree for `ORDER BY expression LIMIT K` is:
    ```
    TopNPrel(ProjectPrel(ExchangePrel(JdbcScanPrel)))
    ```
    NOT `SortPrel(ProjectPrel(...))`. JdbcPushSortWithExpressionsHep will NOT match this topology
    because it matches SortPrel, not TopNPrel. The existing `JdbcPushTopNIntoScanHep` also fails
    because its `findJdbcScan()` only traverses ExchangePrel nodes, not ProjectPrel nodes --
    it returns null for `TopNPrel(ProjectPrel(...))`.

    This rule must handle the TopNPrel case specifically:
    - Pattern: `TopNPrel(any)` -- like JdbcPushTopNIntoScanHep.
    - Constructor: takes `PushdownFunctionRegistry registry` parameter.
    - Create a `findProjectAndScan()` helper method (can be static, shared or duplicated from JdbcPushSortWithExpressionsHep):
      - Starting from the TopNPrel's input, unwrap HepRelVertex.
      - Traverse through at most 2 layers of ExchangePrel to find a ProjectPrel.
      - Then from the ProjectPrel's input, traverse through at most 2 layers of ExchangePrel to find a JdbcScanPrel.
      - Specifically: unwrap -> if ProjectPrel, check its input for JdbcScanPrel (through exchanges). If ExchangePrel, unwrap and check for ProjectPrel, then check its input for JdbcScanPrel (through exchanges).
      - Return a pair (ProjectPrel, JdbcScanPrel) or null if pattern not found.
    - `matches()`:
      - TopNPrel topN = call.rel(0)
      - Find (ProjectPrel, JdbcScanPrel) pair via findProjectAndScan(topN.getInput()).
      - If not found -> return false.
      - If scan already has ORDER BY -> return false.
      - If topN has no field collations -> return false.
      - Check that at least one sort key from ProjectPrel.getProjects() at collation indices is a non-RexInputRef (function expression). If all simple, existing JdbcPushTopNIntoScanHep handles it.
      - Check that all sort key expressions are pushable via registry. If any fails -> return false.
    - `onMatch()`:
      - TopNPrel topN = call.rel(0)
      - Find (ProjectPrel, JdbcScanPrel) pair.
      - Extract sort key expressions from ProjectPrel.getProjects() at TopNPrel.getCollation() field indices.
      - Chain two clone calls on the scan:
        1. `scan.cloneWithSortKeyExpressions(topN.getCollation(), sortKeyExprs)` -- stores sort keys + collation
        2. `.cloneWithLimit(topN.getLimit())` -- stores the TopN limit
      - `call.transformTo(withSortAndLimit);`
    - Give it a descriptive name: `"JdbcPushTopNWithExpressionsHep"`.
