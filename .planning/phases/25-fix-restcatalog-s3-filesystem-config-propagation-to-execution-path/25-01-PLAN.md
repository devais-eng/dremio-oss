<objective>
Fix S3 filesystem config propagation by eagerly merging configPropertyList into the Hadoop Configuration during plugin start(), before the filesystem cache is created.

Purpose: RESTCATALOG sources pointed at S3-compatible backends (MinIO, SeaweedFS, Azure) fail with credential errors because configPropertyList properties (fs.s3a.endpoint, fs.s3a.access.key, etc.) are only merged lazily inside the catalog supplier lambda, which runs after DatasetFileSystemCache is already created with an incomplete Configuration. This fix mirrors the FileSystemPlugin.initializeFsConf() pattern.

Output: Three modified files -- IcebergCatalogPlugin (hook + merge), RestIcebergCatalogPlugin (override), TestRestIcebergCatalogPlugin (unit test)
</objective>

2. Add a protected merge method (directly after `getConfigProperties()`):

```java
/**
 * Eagerly merges properties from {@link #getConfigProperties()} into the filesystem
 * configuration adapter. Must be called in {@link #start()} before {@link #createFSCache()}
 * so that getFsConfCopy() returns a fully-populated Configuration.
 */
protected void mergeConfigPropertiesIntoFsConf() {
    List<Property> properties = getConfigProperties();
    if (properties != null && !properties.isEmpty()) {
        Configuration conf = fsConfAdapter.getConfiguration();
        for (Property p : properties) {
            conf.set(p.name, p.value);
        }
    }
}
```

3. Modify `start()` (currently at line 272-278) to call `mergeConfigPropertiesIntoFsConf()` AFTER `validateOnStart()` but BEFORE `createCatalog()` and `createFSCache()`:

```java
    validateOnStart();

    catalogAccessor = createCatalog(fsConfAdapter.getConfiguration());
    hadoopFs = createFSCache();
    isOpen.set(true);
}
```
