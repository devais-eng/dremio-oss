  <files>

  <action>
    Modify `distribution/docker/Dockerfile` to install the native ADBC PostgreSQL driver.

    Add the dbc CLI installation and driver download in the runtime stage (after the `FROM ${JAVA_IMAGE} AS runtime` line and before the `USER dremio` line), as root:

    ```dockerfile
    # Install native ADBC PostgreSQL driver for high-performance Arrow-native query execution.
    # The dbc CLI (from columnar.tech) manages ADBC driver installation and versioning.
    # The JNI bridge is bundled inside adbc-driver-jni.jar (self-extracting),
    # but the database-specific driver .so must be installed separately.
    RUN apt-get update \
        && apt-get install -y --no-install-recommends curl ca-certificates \
        && curl -LsSf https://dbc.columnar.tech/install.sh | sh \
        && export PATH="$HOME/.cargo/bin:$PATH" \
        && dbc install postgresql \
        && apt-get remove -y curl \
        && apt-get autoremove -y \
        && rm -rf /var/lib/apt/lists/*

    # Make ADBC native drivers discoverable by the JNI driver manager.
    # The dbc CLI installs to ~/.config/columnar/adbc_drivers/ by default.
    ENV LD_LIBRARY_PATH="/root/.config/columnar/adbc_drivers:${LD_LIBRARY_PATH}"
    ```

    IMPORTANT considerations:
    - The `dbc install postgresql` runs as root during Docker build. The `.so` file location will be under `/root/.config/columnar/adbc_drivers/` (root's home).
    - After the `USER dremio` switch, Dremio runs as uid 999. The .so must be readable. Add a chmod or copy step:
      ```dockerfile
      # Copy ADBC drivers to a system-wide location accessible by the dremio user
      RUN mkdir -p /opt/adbc/drivers \
          && cp /root/.config/columnar/adbc_drivers/*.so /opt/adbc/drivers/ 2>/dev/null || true \
          && chmod -R 755 /opt/adbc/drivers
      ENV LD_LIBRARY_PATH="/opt/adbc/drivers:${LD_LIBRARY_PATH}"
      ```
    - If `dbc` CLI is not available or the install script URL is wrong, try the alternative approach of directly downloading the ADBC release tarball:
      ```dockerfile
      RUN curl -L https://github.com/apache/arrow-adbc/releases/download/apache-arrow-adbc-22/adbc_driver_postgresql-1.4.0-linux-amd64.tar.gz \
          | tar xz -C /opt/adbc/drivers/
      ```
      Use whichever approach works. The key requirement is that `libadbc_driver_postgresql.so` ends up on LD_LIBRARY_PATH.
    - Place these commands BEFORE the `USER dremio` line.
    - Keep the rest of the Dockerfile unchanged.
  </action>

  <action>
    Create `plugins/jdbc-postgresql/src/test/java/com/dremio/plugins/jdbc/postgresql/TestPostgresAdbc.java`.

    This test class verifies the ADBC execution path end-to-end against a real PostgreSQL instance using Testcontainers. Follow the patterns established by TestPostgresTypeMapping, TestPostgresPushdown, and TestPostgresSchemaDiscovery.

    **Test class structure:**
    - Use `@ClassRule public static final PostgresTestContainer PG = new PostgresTestContainer();` for the container lifecycle.
    - In `@BeforeClass`: Create the test table, insert test data via JDBC (using the container's JDBC URL). Then create an `AdbcConnectionFactory` using the PostgreSQL URI from the container and a `RootAllocator`.
    - In `@AfterClass`: Close the factory and allocator.

    **Test methods:**

    1. `testAdbcConnectionFactoryOpenClose()`: Verify AdbcConnectionFactory can open() and create a connection. Open a connection, close it. Assert no exceptions.

    2. `testAdbcRecordReaderBasicQuery()`: Create a JdbcSubScan with SQL `SELECT "id", "name" FROM "public"."adbc_test"`, no bind params, and the table's BatchSchema. Create an AdbcRecordReader with the factory. Call setup() with a mock/simple OutputMutator (or use the existing test patterns for OutputMutator). Call next() and verify it returns the expected row count. Verify the Arrow vectors contain the correct values.
       - NOTE: This test creates AdbcRecordReader directly, bypassing JdbcStoragePlugin. The test constructs the necessary dependencies manually.
       - If creating a real OutputMutator is too complex (it may require OperatorContext), simplify: directly test AdbcConnectionFactory + JniStatement + ArrowReader without going through the full RecordReader lifecycle. Create a connection, create a statement, set SQL, execute, read batches, verify row counts and values.

    3. `testAdbcPlaceholderTranslation()`: Create SQL with bind params `SELECT * FROM "public"."adbc_test" WHERE "id" > ?` with a bind param (INTEGER, 1). Translate via `SqlBuilder.jdbcToPostgresPlaceholders()`. Execute via ADBC statement with the bind root. Verify fewer rows are returned than the total.

    4. `testAdbcSchemaDiscovery()`: Create an AdbcSchemaFetcher with the factory. Call `getTableSchema("public", "adbc_test")`. Verify the BatchSchema has the expected fields with correct Arrow types. Verify `listSchemas()` includes "public" but not "pg_catalog" or "information_schema". Verify `listTables("public")` includes "adbc_test".

    5. `testAdbcTypeMapping()`: Insert rows with various PostgreSQL types (INTEGER, BIGINT, FLOAT8, VARCHAR, BOOLEAN, DATE, TIMESTAMP, NUMERIC). Query via ADBC and verify the Arrow batch contains correctly typed vectors.

    **Test table setup SQL:**
    ```sql
    CREATE TABLE IF NOT EXISTS adbc_test (
        id INTEGER PRIMARY KEY,
        name VARCHAR(100),
        amount NUMERIC(10,2),
        is_active BOOLEAN,
        created_date DATE,
        created_at TIMESTAMP,
        score DOUBLE PRECISION,
        big_id BIGINT
    );
    INSERT INTO adbc_test VALUES (1, 'Alice', 100.50, true, '2024-01-15', '2024-01-15 10:30:00', 95.5, 1000000001);
    INSERT INTO adbc_test VALUES (2, 'Bob', 200.75, false, '2024-02-20', '2024-02-20 14:45:00', 87.3, 1000000002);
    INSERT INTO adbc_test VALUES (3, 'Charlie', 350.00, true, '2024-03-10', '2024-03-10 09:15:00', 92.1, 1000000003);
    ```

    **IMPORTANT test execution note:** These tests require the native `libadbc_driver_postgresql.so` to be installed on the machine running the tests. If the native library is not available, the tests should be annotated with `@Ignore("Requires native ADBC driver -- run with -Dadbc.test.enabled=true")` or use an `Assume.assumeTrue()` guard:
    ```java
    @Before
    public void checkAdbcAvailable() {
        Assume.assumeTrue("ADBC native driver not available", AdbcConnectionFactory.isAvailable());
    }
    ```
    This ensures tests are skipped gracefully in CI environments without the native driver.
