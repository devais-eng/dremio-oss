    3. **AdbcConnectionFactory.java**: Create `plugins/jdbc-base/src/main/java/com/dremio/plugins/jdbc/pool/AdbcConnectionFactory.java` with a **two-phase lifecycle** (construct, then open) and **bounded concurrency** via Semaphore:
       - **Constructor** `AdbcConnectionFactory(String connectionUri, BufferAllocator allocator, int maxConnections)`: Stores the URI, allocator, and creates a `java.util.concurrent.Semaphore(maxConnections)` as final fields. The `maxConnections` parameter comes from `BaseJdbcConf.poolSize` — reusing the same user-facing config that controls HikariCP pool size. Does NOT create the JniDriver or AdbcDatabase yet. The factory is inert after construction.
       - **`open()` method**: Creates the JniDriver using the stored allocator. Builds a parameter map with `JniDriver.PARAM_DRIVER` set to `"adbc_driver_postgresql"` and `AdbcDriver.PARAM_URI` set to the stored connection URI. Calls `driver.open(params)` to create and store the `AdbcDatabase` reference. This is the method that can throw if the native driver is unavailable. After `open()`, the factory is ready to create connections.
       - **`openConnection()` method**: Acquires a semaphore permit (blocking if at capacity), then creates a new connection via `database.connect()`. Wraps the returned `AdbcConnection` in a delegating wrapper (`BoundedAdbcConnection`) that releases the semaphore permit when `close()` is called. If `database.connect()` throws, the permit is released immediately before re-throwing. This bounds the maximum concurrent ADBC connections to `maxConnections`, preventing PostgreSQL `max_connections` exhaustion under load.
         ```java
         public AdbcConnection openConnection() throws AdbcException, InterruptedException {
             permits.acquire();
             try {
                 AdbcConnection conn = database.connect();
                 return new BoundedAdbcConnection(conn, permits);
             } catch (Exception e) {
                 permits.release();
                 throw e;
             }
         }
         ```
       - **`BoundedAdbcConnection`** inner class: Delegates all `AdbcConnection` methods to the wrapped connection. Overrides `close()` to first close the delegate, then `permits.release()`. This ensures the permit is always released even if the connection was never used.
       - **`close()` method**: Closes the AdbcDatabase (if not null). Implements AutoCloseable.
       - **`isAvailable()` static method**: Attempts to load `org.apache.arrow.adbc.driver.jni.JniDriver` via Class.forName and returns true/false. Used for AUTO mode probing.
       - IMPORTANT: Do NOT pool/reuse AdbcConnection — each query gets a fresh connection. The Semaphore only bounds concurrency (same role as HikariCP's `maximumPoolSize`). One AdbcDatabase per source lifecycle, one fresh AdbcConnection per query, bounded by `maxConnections`.

    4. **SqlBuilder.java**: Add a static utility method `jdbcToPostgresPlaceholders(String sql, int paramCount)`:
       ```java
       public static String jdbcToPostgresPlaceholders(String sql, int paramCount) {
           if (paramCount == 0) return sql;
           StringBuilder sb = new StringBuilder(sql.length() + paramCount * 2);
           int idx = 0;
           for (int i = 0; i < sql.length(); i++) {
               char c = sql.charAt(i);
               if (c == '?' && idx < paramCount) {
                   idx++;
                   sb.append('$').append(idx);
               } else {
                   sb.append(c);
               }
           }
           return sb.toString();
       }
       ```
       This is safe because our SqlBuilder never generates `?` inside string literals -- all literal values are bind params, and column/table names are double-quoted identifiers.

       - `testPlaceholderTranslationInClause()`: input `WHERE a IN (?, ?, ?)`, paramCount=3, output `WHERE a IN ($1, $2, $3)`

    Create `plugins/jdbc-base/src/main/java/com/dremio/plugins/jdbc/reader/AdbcRecordReader.java` that extends `AbstractRecordReader` (same base as JdbcRecordReader).

    NOTE: This task is intentionally dense (11 vector types, bind root construction, full setup/next/close lifecycle). It is kept as one task because all pieces are in a single file and are tightly coupled -- splitting would create tasks that cannot be verified independently.

    **Constructor:** Takes `OperatorContext context`, `JdbcSubScan config`, `AdbcConnectionFactory factory`.

    **setup(OutputMutator output):**
    1. Register output vectors from the full schema exactly as JdbcRecordReader does -- iterate projected columns (or all columns if star query), find each field in fullSchema, add to OutputMutator via TypeHelper.getValueVectorClass().
    2. Open an ADBC connection: `AdbcConnection conn = factory.openConnection();`
    3. Create statement: `AdbcStatement stmt = conn.createStatement();`
    4. Translate SQL: `String adbcSql = SqlBuilder.jdbcToPostgresPlaceholders(config.getSql(), config.getBindParams().size());`
    5. Set SQL: `stmt.setSqlQuery(adbcSql);`
    6. If bind params are not empty, build a VectorSchemaRoot from the bind params and call `stmt.bind(bindRoot)`:
       - Create a `buildBindRoot(BufferAllocator allocator, List<BindParam> params)` private helper
       - For each BindParam, map its SqlTypeName to an Arrow type: INTEGER->Int(32,true), BIGINT->Int(64,true), FLOAT/REAL->FloatingPoint(SINGLE), DOUBLE->FloatingPoint(DOUBLE), VARCHAR/CHAR->Utf8, BOOLEAN->Bool, DATE->Date(DAY), TIME->Utf8 (string fallback), TIMESTAMP->Timestamp(MILLISECOND,null), DECIMAL->Utf8 (convert to string per research -- ADBC PG driver doesn't support Decimal128 binding), TINYINT/SMALLINT->Int(32,true)
       - Create Field for each param named "$1", "$2", etc.
       - Allocate VectorSchemaRoot, set values using the appropriate vector type, setRowCount(1)
       - IMPORTANT: For DATE values stored as epoch millis Long in BindParam, convert to days (divide by 86400000) for DateDayVector. For TIMESTAMP stored as epoch millis Long, set directly on TimeStampMilliVector. For DECIMAL, convert to string and use VarCharVector.
    7. Execute: `AdbcStatement.QueryResult result = stmt.executeQuery();`
    8. Get reader: `this.arrowReader = result.getReader();`

    **next():**
    1. Call `arrowReader.loadNextBatch()` -- if false, return 0
    2. Get `VectorSchemaRoot batch = arrowReader.getVectorSchemaRoot();`
    3. Get `int rowCount = batch.getRowCount();`
    4. For each field in the registered output vectors: find the corresponding source vector in the ADBC batch by field name. Copy data from the ADBC vector to the Dremio output vector.
       - IMPORTANT anti-pattern: Do NOT share ADBC ArrowReader vectors directly with OutputMutator. The ArrowReader's VectorSchemaRoot uses its own allocator. Must copy/transfer data to Dremio's allocator-managed vectors.
       - Use a `transferVector(ValueVector src, ValueVector dst, int rowCount)` helper that handles each vector type (IntVector, BigIntVector, Float4Vector, Float8Vector, BitVector, VarCharVector, VarBinaryVector, DecimalVector, DateMilliVector, TimeMilliVector, TimeStampMilliVector).
       - For each type: iterate rows 0..rowCount-1, check `src.isNull(i)`, if not null copy the value using `setSafe`.
       - Handle type mismatches gracefully: if ADBC returns a DateDayVector but Dremio expects DateMilliVector, convert (day * 86400000L). If ADBC returns TimeStampMicroVector but Dremio expects TimeStampMilliVector, convert (micro / 1000).
    5. Set value counts on all output vectors.
    6. Return rowCount.

    **close():**
    1. Close arrowReader (if not null)
    2. Close AdbcStatement (if not null)
    3. Close AdbcConnection (if not null)
    4. Close any VectorSchemaRoot used for bind params
    5. Log warnings on close errors (same pattern as JdbcRecordReader)

    Keep the same try-catch-log pattern as JdbcRecordReader for all close operations.
