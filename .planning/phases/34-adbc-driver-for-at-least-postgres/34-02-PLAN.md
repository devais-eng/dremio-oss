    1. **AdbcSchemaFetcher.java**: Create `plugins/jdbc-base/src/main/java/com/dremio/plugins/jdbc/schema/AdbcSchemaFetcher.java`:
       - Constructor takes `AdbcConnectionFactory factory`
       - `listSchemas()`: Opens an AdbcConnection, calls `conn.getObjects(GetObjectsDepth.DB_SCHEMAS, null, null, null, null, null)`, reads the ArrowReader to extract schema names. Filter out system schemas using the same `isSystemSchema()` logic as JdbcSchemaFetcher. Returns `List<String>`. Close connection after use.
       - `listTables(String schemaName)`: Opens an AdbcConnection, calls `conn.getObjects(GetObjectsDepth.TABLES, null, schemaName, "%", new String[]{"TABLE", "VIEW"}, null)`, reads the ArrowReader to extract table names. Returns `List<String>`. Close connection after use.
       - `tableExists(String schemaName, String tableName)`: Opens an AdbcConnection, calls `conn.getObjects(GetObjectsDepth.TABLES, null, schemaName, tableName, new String[]{"TABLE", "VIEW"}, null)`, checks if any results. Returns boolean. Close connection after use.
       - `getTableSchema(String schemaName, String tableName)`: Opens an AdbcConnection, calls `conn.getTableSchema(null, schemaName, tableName)`, converts the returned Arrow Schema to BatchSchema. Map Arrow types to Dremio-compatible types (strip timezone from Timestamp, convert DateDay to DateMilli -- same normalization as JdbcSchemaFetcher.mapJdbcType). Returns `BatchSchema`. Close connection after use.
       - `isSystemSchema(String schemaName)`: Same logic as JdbcSchemaFetcher -- filters information_schema, pg_catalog, pg_toast*, pg_temp_*.
       - NOTE: The ADBC `getObjects()` returns a nested Arrow schema: catalog_name -> db_schemas (list) -> db_schema_name, db_schema_tables (list) -> table_name, table_type. Parse this structure carefully using VectorSchemaRoot field accessors. The exact nested structure requires reading the list vectors and struct vectors from the ArrowReader result.

    2. **JdbcStoragePlugin.java**: Add ADBC lifecycle management:
       - Add fields:
         - `private RootAllocator adbcAllocator;` -- dedicated allocator for ADBC. Must be declared, initialized in start(), and closed in close().
         - `private volatile AdbcConnectionFactory adbcFactory;`
         - `private volatile AdbcSchemaFetcher adbcSchemaFetcher;`
         - `private volatile ProtocolMode effectiveProtocolMode = ProtocolMode.JDBC;`
       - Add method `public ProtocolMode getEffectiveProtocolMode()` -- returns the resolved effectiveProtocolMode.
       - Add method `public AdbcConnectionFactory getAdbcFactory()` -- returns adbcFactory (may be null if JDBC mode).
       - Add protected method `createAdbcSchemaFetcher(AdbcConnectionFactory factory)` -- returns `new AdbcSchemaFetcher(factory)`. Subclasses can override.
       - Add protected method `createAdbcRecordReader(OperatorContext ctx, JdbcSubScan config, AdbcConnectionFactory factory)` -- returns `new AdbcRecordReader(ctx, config, factory)`. Subclasses can override.
       - Modify `start()`:
         ```java
         pool = new JdbcConnectionPool(conf);
         schemaFetcher = createSchemaFetcher(pool);

         ProtocolMode configured = conf.getProtocolMode();
         String adbcUri = conf.adbcUri();
         if ((configured == ProtocolMode.ADBC || configured == ProtocolMode.AUTO) && adbcUri != null) {
             try {
                 adbcAllocator = new RootAllocator();
                 adbcFactory = new AdbcConnectionFactory(adbcUri, adbcAllocator, conf.poolSize);
                 adbcFactory.open();
                 adbcSchemaFetcher = createAdbcSchemaFetcher(adbcFactory);
                 effectiveProtocolMode = ProtocolMode.ADBC;
                 logger.info("ADBC backend initialized for source '{}'", name);
             } catch (Exception e) {
                 if (configured == ProtocolMode.ADBC) {
                     throw new IOException("ADBC mode requested but native driver unavailable: " + e.getMessage(), e);
                 }
                 // AUTO: fall back to JDBC
                 logger.info("ADBC not available for source '{}', falling back to JDBC: {}", name, e.getMessage());
                 effectiveProtocolMode = ProtocolMode.JDBC;
                 closeAdbcResources(); // clean up partial init
             }
         } else {
             effectiveProtocolMode = ProtocolMode.JDBC;
         }
         ```
         IMPORTANT: Guard `adbcUri` for null. If `conf.adbcUri()` returns null (meaning this database type does not support ADBC), skip ADBC init entirely even if protocolMode is AUTO or ADBC. This prevents NPE for databases like Oracle that have no ADBC URI.
       - Add private `closeAdbcResources()` helper:
         ```java
         private void closeAdbcResources() {
             if (adbcFactory != null) {
                 try { adbcFactory.close(); } catch (Exception e) { logger.warn("Error closing ADBC factory", e); }
                 adbcFactory = null;
             }
             adbcSchemaFetcher = null;
             if (adbcAllocator != null) {
                 try { adbcAllocator.close(); } catch (Exception e) { logger.warn("Error closing ADBC allocator", e); }
                 adbcAllocator = null;
             }
         }
         ```
       - Modify `close()`: Call `closeAdbcResources()` before closing the JDBC pool.
       - Modify the existing concrete method `getDatasetMetadata()`: Add a protocol mode check at the top of the method body. If `effectiveProtocolMode == ProtocolMode.ADBC && adbcSchemaFetcher != null`, branch to call `adbcSchemaFetcher.getTableSchema()` to get the BatchSchema instead of using the JDBC-based schema fetcher. This is NOT an "override" -- it is modifying the existing concrete method to add a conditional branch.
       - Similarly modify the existing concrete method `listDatasetHandles()`: If `effectiveProtocolMode == ProtocolMode.ADBC && adbcSchemaFetcher != null`, call `adbcSchemaFetcher.listSchemas()` and `adbcSchemaFetcher.listTables()` instead of the JDBC schema fetcher.
       - Similarly modify `getDatasetHandle()` and `containerExists()` to check `effectiveProtocolMode == ProtocolMode.ADBC` and branch to `adbcSchemaFetcher.tableExists()` / `adbcSchemaFetcher.getTableSchema()` as appropriate.
       - Keep JDBC pool always initialized regardless of protocol mode -- it's used for health checks (`getState()`) and as fallback.

    1. **BaseJdbcConf.java**: Add protocol mode support:
       - Add import for ProtocolMode
       - Add field: `@Tag(4) @NotMetadataImpacting public ProtocolMode protocolMode = ProtocolMode.AUTO;`
         Use Tag(4) which is the next available tag number after Tag(3) validationQuery.
       - Add method `public ProtocolMode getProtocolMode() { return protocolMode != null ? protocolMode : ProtocolMode.AUTO; }` with null-safety.
       - Add method with default implementation returning null (meaning ADBC not supported for this database type):
         ```java
         public String adbcUri() {
             return null; // Subclasses override to provide ADBC connection URI
         }
         ```
       - IMPORTANT: The `protocolMode` field lives ONLY in BaseJdbcConf at Tag(4). Subclasses (PostgresConf, OracleConf) do NOT declare their own protocolMode field. This avoids Protostuff serialization conflicts where two fields with the same Java name at different tag numbers would collide across the inheritance chain.

    2. **PostgresConf.java**: Add adbcUri only (NO protocolMode field):
       - Do NOT add a `@Tag(50) protocolMode` field to PostgresConf. The `@Tag(4) protocolMode` field inherited from BaseJdbcConf is sufficient. Adding a second field named `protocolMode` at a different tag number would cause a Protostuff serialization bug with two distinct wire tags for the same logical field.
       - Override `adbcUri()` only:
         ```java
         @Override
         public String adbcUri() {
             StringBuilder uri = new StringBuilder("postgresql://");
             if (username != null) {
                 uri.append(username);
                 String pw = getPassword();
                 if (pw != null) {
                     uri.append(":").append(pw);
                 }
                 uri.append("@");
             }
             uri.append(hostname).append(":").append(port).append("/").append(databaseName);
             if (useSsl) {
                 uri.append("?sslmode=require");
             }
             return uri.toString();
         }
         ```
         This produces URIs like `postgresql://user:pass@host:5432/dbname` which the ADBC PG driver understands (it uses libpq's connection string format).
       - The existing `newPlugin()` anonymous subclass does not need additional overrides for ADBC. The base JdbcStoragePlugin methods (createAdbcRecordReader, createAdbcSchemaFetcher) provide defaults that work for PostgreSQL.
