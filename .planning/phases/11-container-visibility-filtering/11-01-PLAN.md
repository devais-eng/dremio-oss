  <action>
Add two new public methods to RbacService, placed after the existing `hasAnyPdsGrant()` method (in the "REST API support" section, or create a new "Container visibility" section):

**Method 1: `getAccessibleObjectPaths(String userName)`**
- Returns `Set<String>` of all object paths the user has grants on (via any of their roles + PUBLIC)
- Does NOT check admin (caller handles admin short-circuit)
- Implementation: collect user's roleIds from `membershipStore.listByUser(userName)`, add `PUBLIC_ROLE_ID`, then stream `grantStore.listAll()` filtering by `roleIds.contains(grant.getRoleId())`, map to `grant.getObjectPath()`, collect to `Set`
- Add `java.util.Set` and `java.util.stream.Collectors` imports (Collectors already imported)
- Add `java.util.HashSet` import for the `Collectors.toSet()` return type (or use `Collectors.toCollection(HashSet::new)` — simpler to just use `Collectors.toSet()`)
- Preconditions check: userName not null/empty

**Method 2: `hasAccessibleChildUnderPath(String userName, String containerPath)`**
- Returns `boolean` — true if the user has at least one grant on any object whose path starts with `containerPath + "."` (dot prevents false prefix matches like "myspace" matching "myspace2.x")
- Short-circuits: `isAdminMember(userName)` returns true immediately
- Implementation: collect roleIds + PUBLIC, iterate `grantStore.listAll()`, check `roleIds.contains(grant.getRoleId()) && grant.getObjectPath().startsWith(prefix)`
- Preconditions check: both args not null/empty
- This method is used for single-container checks (folder visibility in child listings)

Add a section comment `// Container visibility` above both methods.

**Why two methods:** `getAccessibleObjectPaths()` is for batch use in top-level listings (one grant scan, many containers). `hasAccessibleChildUnderPath()` is for single-container checks in child listings where only one folder is checked per call. Research Pitfall 5 explains the performance rationale.

Two changes in CatalogServiceHelper:

**Change 1: Filter spaces AND sources in `getTopLevelCatalogItems()` (around line 366)**

Add a private helper method `getUserAccessibleObjectPaths(String userName)` that:
1. Returns `null` if `rbacService == null || dremioConfig == null || !dremioConfig.getBoolean(DremioConfig.RBAC_ENABLED)` (RBAC disabled — show everything)
2. Returns `null` if `rbacService.isAdminMember(userName)` (admin — show everything)
3. Otherwise returns `rbacService.getAccessibleObjectPaths(userName)`

Add a private helper `hasChildUnder(Set<String> accessiblePaths, String containerName)`:
- Returns `accessiblePaths.stream().anyMatch(p -> p.startsWith(containerName + "."))`

In `getTopLevelCatalogItems()`, BEFORE the space loop:
```java
String userName = securityContext.getUserPrincipal().getName();
Set<String> accessiblePaths = getUserAccessibleObjectPaths(userName);
```

Change the space loop from:
```java
for (SpaceConfig spaceConfig : namespaceService.getSpaces()) {
    topLevelItems.add(CatalogItem.fromSpaceConfig(spaceConfig));
}
```
To:
```java
for (SpaceConfig spaceConfig : namespaceService.getSpaces()) {
    if (accessiblePaths == null || hasChildUnder(accessiblePaths, spaceConfig.getName())) {
        topLevelItems.add(CatalogItem.fromSpaceConfig(spaceConfig));
    }
}
```

**Also filter sources** — apply the same pattern to the source loop:
```java
for (SourceConfig sourceConfig : sourceService.getSources()) {
    if (accessiblePaths == null || hasChildUnder(accessiblePaths, sourceConfig.getName())) {
        topLevelItems.add(CatalogItem.fromSourceConfig(sourceConfig));
    }
}
```
With deny-by-default PDS (Phase 10 fix), PDS without grants are inaccessible, so the grant prefix scan correctly identifies sources with no accessible children.

Add `java.util.Set` import.

Replace the current folder/container pass-through:

// FOLDER, SPACE, SOURCE, HOME are always visible (containers).

if (container.getType() == NameSpaceContainer.Type.FOLDER) {

Note: `isVisibleToUser()` already receives `userName` as a parameter. The `rbacService` null check and RBAC-disabled check already happen in `filterByVisibility()` before `isVisibleToUser()` is called, so no additional guards are needed inside isVisibleToUser for the folder case.
