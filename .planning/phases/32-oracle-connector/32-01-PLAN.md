    **1. JdbcStoragePlugin.java** — Add a `createSqlBuilder()` factory method (public, same pattern as `createSchemaFetcher`):
    ```java
    public SqlBuilder createSqlBuilder() {
        return new SqlBuilder();
    }
    ```
    Add import for `com.dremio.plugins.jdbc.planning.SqlBuilder`.

    **2. JdbcScanPrel.java** — In `getPhysicalOperator(PhysicalPlanCreator creator)`, resolve the plugin and use its `createSqlBuilder()` instead of the hardcoded `this.sqlBuilder` field.

    **Verified approach** (confirmed via codebase analysis — `PhysicalPlanCreator` has `getContext()` → `QueryContext` has `getCatalogService()` → `CatalogService.getSource(name)` returns `StoragePlugin`):

    In `getPhysicalOperator()`, replace usage of `this.sqlBuilder` with a dynamically resolved SqlBuilder:
    ```java
    StoragePlugin rawPlugin = creator.getContext().getCatalogService()
        .getSource(getPluginId().getName());
    SqlBuilder sb = (rawPlugin instanceof JdbcStoragePlugin)
        ? ((JdbcStoragePlugin) rawPlugin).createSqlBuilder()
        : new SqlBuilder();
    String sql = sb.buildSql(schemaName, tableName, getProjectedColumns(), whereClause, limit);
    ```

    This requires NO changes to JdbcScanPrel's constructor, clone methods, or JdbcScanPrule. The `sqlBuilder` field can be removed entirely (it is only used in `getPhysicalOperator()`), or kept as a fallback — removing it is cleaner.

    Add necessary imports: `com.dremio.exec.store.StoragePlugin`, `com.dremio.plugins.jdbc.JdbcStoragePlugin`.

    **Backward compatibility note:** PostgresConf.newPlugin() does NOT need to override `createSqlBuilder()` — the base `SqlBuilder` already generates correct `LIMIT N` syntax which is valid for PostgreSQL. Only Oracle (and future databases with non-standard LIMIT syntax) need to override this factory method.

    **3. OracleConf.java** — Following PostgresConf pattern exactly:
    - Package: `com.dremio.plugins.jdbc.oracle`
    - `@SourceType(value = "ORACLE_DB", label = "Oracle", uiConfig = "oracle-layout.json")`
    - `extends BaseJdbcConf<OracleConf, JdbcStoragePlugin>`
    - Connection fields (Tags 10-12): `hostname` (String), `port` (int, default 1521), `serviceName` (String) — NOT databaseName
    - Auth fields (Tags 20-21): `username` (String), `password` (SecretRef @Secret)
    - Encryption fields (Tags 30-31): `useSsl` (boolean), `encryptionValidationMode` (EncryptionValidationMode)
    - Performance fields (Tags 40-41): `fetchSize` (int, 4096), `queryTimeoutSec` (int, 0)
    - Constructor: set `this.validationQuery = "SELECT 1 FROM DUAL"`
    - `jdbcUrl()`: returns `"jdbc:oracle:thin:@//" + hostname + ":" + port + "/" + serviceName`
      - For SSL: Oracle uses connection properties, not URL params. When `useSsl` is true, set `oracle.net.ssl_server_dn_match` in `getConnectionProperties()`. The URL itself does not change (simple v1.5 approach).
    - `driverClassName()`: returns `"oracle.jdbc.OracleDriver"`
    - `getUsername()`: returns `username`
    - `getPassword()`: same SecretRef pattern as PostgresConf
    - `getConnectionProperties()`: if `queryTimeoutSec > 0`, set `oracle.jdbc.ReadTimeout` to `queryTimeoutSec * 1000` (milliseconds). If `useSsl`, set `oracle.net.ssl_server_dn_match` based on `encryptionValidationMode`.
    - `newPlugin()`: Same anonymous subclass pattern as PostgresConf, overriding `createSchemaFetcher` (returns `new OracleSchemaFetcher(pool)`), `createRecordReader` (returns `new OracleRecordReader(ctx, config, pool)`), and `createSqlBuilder` (returns `new OracleSqlBuilder()`).

    **4. OracleSchemaFetcher.java** — Following PostgresSchemaFetcher pattern:
    - Extends `JdbcSchemaFetcher`
    - Constructor: `public OracleSchemaFetcher(JdbcConnectionPool pool) { super(pool); }`
    - Override `mapJdbcType(int jdbcType, String typeName, int precision, int scale)`:
      - `BINARY_FLOAT` (typeName "binary_float" or jdbcType 100): -> `FloatingPoint(SINGLE)`
      - `BINARY_DOUBLE` (typeName "binary_double" or jdbcType 101): -> `FloatingPoint(DOUBLE)`
      - `CLOB` (Types.CLOB=2005) or `NCLOB` (Types.NCLOB=2011): -> `Utf8`
      - `NVARCHAR` (Types.NVARCHAR=-9) or `NCHAR` (Types.NCHAR=-15): -> `Utf8`
      - `Types.NUMERIC` with scale == -127: -> `FloatingPoint(DOUBLE)` (Oracle FLOAT sentinel)
      - `Types.NUMERIC` with precision == 0: -> `FloatingPoint(DOUBLE)` (bare NUMBER)
      - `TIMESTAMP_WITH_TIMEZONE` (Types.TIMESTAMP_WITH_TIMEZONE=2014): -> `Timestamp(MILLISECOND, null)` (drop TZ)
      - Everything else: delegate to `super.mapJdbcType()`
    - Override `isSystemSchema(String schemaName)` — DO NOT call `super.isSystemSchema()` (base checks PG-specific schemas). Full replacement:
      ```java
      private static final Set<String> ORACLE_SYSTEM_SCHEMAS = Set.of(
          "sys", "system", "ctxsys", "mdsys", "xdb", "outln",
          "xs$null", "flows_files", "dvsys", "audsys", "dbsnmp",
          "gsmadmin_internal", "lbacsys", "orddata", "ordsys",
          "wmsys", "appqossys", "dbsfwuser", "olapsys"
      );
      ```
      Return `schemaName != null && ORACLE_SYSTEM_SCHEMAS.contains(schemaName.toLowerCase())`

    **5. OracleRecordReader.java** — Structural placeholder following PostgresRecordReader pattern:

    - No method overrides needed for v1.5 (base reader handles TIMESTAMP via `rs.getTimestamp()`, CLOB via `rs.getString()`, BLOB via `rs.getBytes()` correctly)
