      - `getUsername()`/`getPassword()`: delegate to OracleTestContainer static methods
      - `newPlugin()`: throws `UnsupportedOperationException`

    **3. TestOracleTypeMapping.java** — Follow TestPostgresTypeMapping pattern but with Oracle types:
    - `@ClassRule public static final DremioOracleContainer ORACLE = OracleTestContainer.ORACLE;`
    - `@BeforeClass`: create pool + OracleSchemaFetcher, then create type_test table:
      ```sql
      CREATE TABLE type_test (
        id NUMBER(10) NOT NULL,
        col_number_ps NUMBER(10,2),
        col_number_bare NUMBER,
        col_float FLOAT,
        col_binary_float BINARY_FLOAT,
        col_binary_double BINARY_DOUBLE,
        col_varchar2 VARCHAR2(100),
        col_nvarchar2 NVARCHAR2(100),
        col_char CHAR(10),
        col_clob CLOB,
        col_nclob NCLOB,
        col_blob BLOB,
        col_raw RAW(100),
        col_date DATE,
        col_timestamp TIMESTAMP(6),
        col_timestamp_tz TIMESTAMP(6) WITH TIME ZONE,
        PRIMARY KEY (id)
      )
      ```
    - Insert test data (see research Section 22 for exact INSERT syntax). Use Oracle-specific syntax:
      ```sql
      INSERT INTO type_test VALUES (
        1, 12345.67, 3.141592653589793, 2.71828, 3.14, 2.718281828459045,
        'hello', N'world', 'pad       ',
        'clob text value', N'nclob text value',
        UTL_RAW.CAST_TO_RAW('binary data'),
        UTL_RAW.CAST_TO_RAW('raw data'),
        TO_DATE('2024-01-15 10:30:00', 'YYYY-MM-DD HH24:MI:SS'),
        TIMESTAMP '2024-01-15 10:30:00.123456',
        TIMESTAMP '2024-01-15 10:30:00.123 +05:30'
      )
      ```
    - `@AfterClass`: close pool
    - `testSchemaMapping()`: Get schema via `schemaFetcher.getTableSchema(schemaName, "TYPE_TEST")`. **IMPORTANT**: Oracle returns UPPERCASE identifiers. The schema name is the username in uppercase: `"TEST_USER"`. The table name is `"TYPE_TEST"`.
      Assert field types:
      - `ID` → `ArrowType.Decimal` (or `ArrowType.Int` depending on how NUMBER(10) maps — check: NUMBER(10) has precision=10, scale=0, so base mapJdbcType returns Decimal(10,0). Assert Decimal.)
      - `COL_NUMBER_PS` → `ArrowType.Decimal` (precision=10, scale=2)
      - `COL_NUMBER_BARE` → `ArrowType.FloatingPoint(DOUBLE)` (Oracle bare NUMBER)
      - `COL_FLOAT` → `ArrowType.FloatingPoint(DOUBLE)` (scale=-127 sentinel)
      - `COL_BINARY_FLOAT` → `ArrowType.FloatingPoint(SINGLE)`
      - `COL_BINARY_DOUBLE` → `ArrowType.FloatingPoint(DOUBLE)`
      - `COL_VARCHAR2` → `ArrowType.Utf8`
      - `COL_NVARCHAR2` → `ArrowType.Utf8`
      - `COL_CHAR` → `ArrowType.Utf8`
      - `COL_CLOB` → `ArrowType.Utf8`
      - `COL_NCLOB` → `ArrowType.Utf8`
      - `COL_BLOB` → `ArrowType.Binary`
      - `COL_RAW` → `ArrowType.Binary`
      - `COL_DATE` → `ArrowType.Timestamp` (Oracle DATE includes time; driver reports as TIMESTAMP)
      - `COL_TIMESTAMP` → `ArrowType.Timestamp`
      - `COL_TIMESTAMP_TZ` → `ArrowType.Timestamp` (TZ dropped by OracleSchemaFetcher)
    - `testNullHandling()`: Insert a row with all NULLs, verify schema is still discoverable
    - `testValueRoundtrip()`: Read back inserted row via raw JDBC, verify sensible values for key columns (varchar2, number, date timestamp value preserves time component)

    Helper methods: `findField(BatchSchema, String)`, `assertFieldType()`, `assertUtf8()`, `assertDecimal()`, `assertFloat4()`, `assertFloat8()`, `assertTimestamp()`, `assertBinary()` — match field names case-insensitively since Oracle returns UPPERCASE.

    **1. TestOracleSchemaDiscovery.java** — Follow TestPostgresSchemaDiscovery pattern:
    - `@ClassRule public static final DremioOracleContainer ORACLE = OracleTestContainer.ORACLE;`
    - `@BeforeClass`: Create pool + OracleSchemaFetcher. Create a test table in the test user's schema:
      ```sql
      CREATE TABLE discovery_table (id NUMBER(10), name VARCHAR2(100))
      ```
      Optionally create a view:
      ```sql
      CREATE VIEW discovery_view AS SELECT * FROM discovery_table
      ```
      Note: In Oracle, the test user's schema is the same as the username (UPPERCASE: `"TEST_USER"`). There is no `CREATE SCHEMA` in Oracle — schemas are tied to users.
    - `testListSchemas()`:
      - Call `schemaFetcher.listSchemas()`
      - Assert `"TEST_USER"` is present (the test user's schema)
      - Assert `"SYS"` is NOT present
      - Assert `"SYSTEM"` is NOT present
      - Assert none of the Oracle system schemas are present (CTXSYS, MDSYS, XDB, etc.)
    - `testListTables()`:
      - Call `schemaFetcher.listTables("TEST_USER")`
      - Assert `"DISCOVERY_TABLE"` is present (UPPERCASE)
      - Assert `"DISCOVERY_VIEW"` is present (UPPERCASE)
    - `testListTablesNonExistentSchema()`:
      - Call `schemaFetcher.listTables("NONEXISTENT")`
      - Assert list is empty (no exception)
    - `testTableExistsForExistingTable()`:
      - `schemaFetcher.tableExists("TEST_USER", "DISCOVERY_TABLE")` returns true
    - `testTableExistsForView()`:
      - `schemaFetcher.tableExists("TEST_USER", "DISCOVERY_VIEW")` returns true
    - `testTableExistsForNonExistent()`:
      - `schemaFetcher.tableExists("TEST_USER", "NONEXISTENT")` returns false
    - `testGetTableSchemaColumns()`:
      - Get schema for `discovery_table`
      - Assert `"ID"` field is present and maps to Decimal (NUMBER(10) → DECIMAL(10,0))
      - Assert `"NAME"` field is present and maps to Utf8
    - `@AfterClass`: close pool

    **2. TestOraclePushdown.java** — Follow TestPostgresPushdown pattern:
    - `@ClassRule public static final DremioOracleContainer ORACLE = OracleTestContainer.ORACLE;`
    - Use `OracleSqlBuilder` (NOT base `SqlBuilder`) for all SQL generation
    - `@BeforeClass`: Create pushdown test table:
      ```sql
      CREATE TABLE pushdown_test (
        id NUMBER(10) NOT NULL,
        name VARCHAR2(100) NOT NULL,
        age NUMBER(3),
        PRIMARY KEY (id)
      )
      ```
      Insert 5 test rows:
      ```sql
      INSERT ALL
        INTO pushdown_test VALUES (1, 'Alice', 30)
        INTO pushdown_test VALUES (2, 'Bob', 25)
        INTO pushdown_test VALUES (3, 'Charlie', 35)
        INTO pushdown_test VALUES (4, 'Dave', 28)
        INTO pushdown_test VALUES (5, 'Eve', 40)
      SELECT 1 FROM DUAL
      ```

    **Pure SQL generation tests (no container needed):**
    - `testSelectAllColumns()`: `OracleSqlBuilder.buildSql("TEST_USER", "test_table", null, null, null)` → `SELECT * FROM "TEST_USER"."test_table"`
    - `testSelectProjectedColumns()`: projects `"id"`, `"name"` → SELECT list with quoted identifiers
    - `testSelectWithWhereClause()`: includes WHERE clause
    - `testSelectWithLimit()`: **CRITICAL** — must contain `FETCH FIRST 100 ROWS ONLY` (NOT `LIMIT 100`)
    - `testSelectWithWhereAndLimit()`: WHERE before FETCH FIRST
    - `testSelectWithProjectionAndFilter()`: projected columns + WHERE
    - `testEmptyProjectionProducesSelectStar()`
    - `testNullWhereClauseOmitted()`
    - `testNullLimitOmitted()`: no FETCH FIRST present when limit is null
    - `testNoLimitKeyword()`: verify the word "LIMIT" does NOT appear in any generated SQL with a limit (Oracle does not support LIMIT)

    **Container-based execution tests:**
    - `testPushdownQueryExecutesAgainstOracle()`: SELECT * executes and returns rows
    - `testFilterPushdownResultCorrectness()`: WHERE "AGE" > 28 returns exactly 3 rows (Alice, Charlie, Eve). **IMPORTANT**: Oracle identifiers are UPPERCASE, so filter on `"AGE"` not `"age"`.
    - `testLimitPushdownResultCorrectness()`: FETCH FIRST 2 ROWS ONLY returns exactly 2 rows
    - `testProjectionPushdownResultCorrectness()`: SELECT "NAME" only
    - `testCombinedPushdownCorrectness()`: projection + filter + limit combined

    All container-based tests use `DriverManager.getConnection(OracleTestContainer.getJdbcUrl(), OracleTestContainer.getUsername(), OracleTestContainer.getPassword())`.

    Note on schema for SQL: In Oracle, the test user's schema is `"TEST_USER"` (UPPERCASE). Use this as the schemaName parameter to `buildSql()` for container-based tests.
