<objective>
Verify JOIN pushdown and ADBC COPY optimization with integration tests against real PostgreSQL and Oracle containers.

Purpose: Confirm that the planner rules, SQL generation, and literal inlining produce correct results end-to-end against actual database engines. The tests are split into two tiers: (A) SQL validity tests that execute generated JOIN SQL directly against database containers to verify correctness and syntax validity, and (B) ADBC literal inlining tests that verify the LiteralInliner produces executable SQL with correct escaping including adversarial input.

IMPORTANT NOTE on test scope: Full planner integration tests (verifying JdbcPushJoinIntoScan fires in the Dremio planner and JoinRel is replaced by JdbcJoinScanPrel) would require SabotNode/DremioTestContext infrastructure with a configured JDBC source. This project does not have that test infrastructure wired -- all existing TestPostgresPushdown/TestOraclePushdown tests use direct JDBC connections against Testcontainers, NOT Dremio's full query engine. The Docker-based UAT scripts in distribution/docker/ (test-verbose-pushdowns.sh, test-all-pushdowns.sh) verify full end-to-end planner behavior via EXPLAIN PLAN and Dremio REST API. These container tests verify the SQL layer (that buildJoinSql produces valid, correct SQL for each database dialect) which is the critical correctness gate.

ADBC-02 end-to-end coverage note: The ADBC literal inlining path (LiteralInliner -> AdbcRecordReader) is verified end-to-end by the Phase 34 Docker tests (test-verbose-pushdowns.sh) which exercise the full ADBC protocol path against a running Dremio instance. The unit tests in Plan 02 (TestLiteralInliner) cover the escaping logic exhaustively including SQL injection safety. The container tests here verify that inlined SQL is executable against real databases.

Output: TestPostgresJoinPushdown (PG join + ADBC COPY tests), TestOracleJoinPushdown (Oracle join tests).
