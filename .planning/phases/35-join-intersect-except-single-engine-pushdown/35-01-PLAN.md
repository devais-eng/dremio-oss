<objective>
Create the planner infrastructure for pushing JOIN operations down to the JDBC source when both sides of the join reference tables on the same plugin instance.

Purpose: Avoid unnecessary data transfer for joins between tables on the same JDBC source -- the source engine computes the join using its own indexes and statistics, returning only the result set.

Output: JdbcJoinScanDrel logical node, JdbcJoinScanPrel physical node, RexToJoinSqlString alias-aware converter, JdbcPushJoinIntoScan LOGICAL rule, SqlBuilder.buildJoinSql(), unit tests.
</objective>

    **CRITICAL ARCHITECTURE: Two-node design (logical + physical), SQL built at physical time.**

    The rule fires at LOGICAL level matching `JoinRel(JdbcScanDrel, JdbcScanDrel)`. At logical level, the children are clean -- no WHERE, LIMIT, ORDER BY, or aggregation state (those are PHYSICAL-phase concerns). The rule produces a `JdbcJoinScanDrel` that carries the raw join components (schema names, table names, join type, ON clause SQL, projected columns, bind params). Later, `JdbcScanPrule`-style conversion (handled inside JdbcJoinScanPrel's constructor/factory or an explicit Prule -- but since JdbcJoinScanDrel implements Rel and we need PHYSICAL conversion, create a simple conversion path) converts it to `JdbcJoinScanPrel`. The `JdbcJoinScanPrel.getPhysicalOperator()` resolves the plugin-provided `SqlBuilder` (for Oracle dialect etc.) and calls `SqlBuilder.buildJoinSql()` to produce the final SQL string.

    **1. Create `JdbcJoinScanDrel` -- logical join scan node carrying raw join components.**

    Package: `com.dremio.plugins.jdbc.planning`

    This class extends `AbstractRelNode` and implements `com.dremio.exec.planner.logical.Rel` (the Dremio logical convention marker). It is a leaf node (no children) that stores:
    - `StoragePluginId pluginId`
    - `String leftSchema`, `String leftTable` (extracted from left scan's TableMetadata path)
    - `String rightSchema`, `String rightTable` (extracted from right scan's TableMetadata path)
    - `org.apache.calcite.rel.core.JoinRelType joinType`
    - `String onClauseSql` (the ON condition as SQL string with ? placeholders)
    - `List<BindParam> conditionBindParams` (bind params from the ON clause conversion)
    - `List<SchemaPath> leftColumns`, `List<SchemaPath> rightColumns` (projected columns from each side)
    - `RelDataType outputRowType` (the join's combined row type, passed from JoinRel.getRowType())

    Key methods:
    - Constructor: takes all fields above plus `RelOptCluster cluster` and `RelTraitSet traitSet`
    - `deriveRowType()`: return the stored `outputRowType`
    - `copy(RelTraitSet, List<RelNode>)`: return clone with new traitSet (leaf node, no inputs)
    - `explainTerms(RelWriter)`: output leftTable, rightTable, joinType, onClauseSql for EXPLAIN

    The traitSet should use `Rel.LOGICAL` convention (same as JdbcScanDrel uses `Rel` convention).

    **2. Create `JdbcJoinScanPrel` -- physical scan node that builds JOIN SQL at getPhysicalOperator() time.**

    This class extends `AbstractRelNode` and implements `com.dremio.exec.planner.physical.Prel` and `com.dremio.exec.planner.physical.LeafPrel` (NOT `ScanPrelBase` -- that requires single-table metadata). Constructor takes the same raw components as JdbcJoinScanDrel:
    - `RelOptCluster cluster`
    - `RelTraitSet traitSet`
    - `StoragePluginId pluginId`
    - `String leftSchema`, `String leftTable`
    - `String rightSchema`, `String rightTable`
    - `org.apache.calcite.rel.core.JoinRelType joinType`
    - `String onClauseSql` (ON condition SQL with ? placeholders)
    - `List<BindParam> conditionBindParams`
    - `List<SchemaPath> leftColumns`, `List<SchemaPath> rightColumns`
    - `RelDataType outputRowType`

    Key methods:
    - `getPhysicalOperator(PhysicalPlanCreator creator)`: This is where SQL is built.
      1. Resolve `SqlBuilder` from the plugin (same pattern as `JdbcScanPrel.getPhysicalOperator()`):
         ```java
         StoragePlugin rawPlugin = creator.getContext().getCatalogService().getSource(pluginId.getName());
         SqlBuilder sb = (rawPlugin instanceof JdbcStoragePlugin)
             ? ((JdbcStoragePlugin) rawPlugin).createSqlBuilder()
             : new SqlBuilder();
         ```
      2. Build the JOIN SQL via `sb.buildJoinSql(leftSchema, leftTable, "t1", rightSchema, rightTable, "t2", SqlBuilder.joinTypeToSql(joinType), onClauseSql, leftColumns, rightColumns)`.
      3. Convert `outputRowType` to `BatchSchema` via `CalciteArrowHelper.fromCalciteRowType(outputRowType)`.
      4. Build merged projected columns from leftColumns + rightColumns.
      5. Create `JdbcGroupScan` with the built SQL, merged projected columns, outputSchema, pluginId, `Collections.singletonList("_join_")` for tableSchemaPath, and conditionBindParams.
      6. Use `creator.props(this, null, outputSchema)` for OpProps.
    - `getMaxParallelizationWidth()` / `getMinParallelizationWidth()`: return 1 (single-node JDBC).
    - `getDistributionAffinity()`: return `DistributionAffinity.SOFT`.
    - `deriveRowType()`: return the stored `outputRowType`.
    - `copy(RelTraitSet, List<RelNode>)`: return clone with new traitSet.
    - `explainTerms(RelWriter)`: output leftTable, rightTable, joinType, onClauseSql, pluginId for EXPLAIN plan.
    - `iterator()`: return `Collections.emptyIterator()` (leaf node, no children).
    - `getEncoding()`: return null (not a filesystem scan).

    Also add accessor methods: `getPluginId()`, `getLeftSchema()`, `getLeftTable()`, `getRightSchema()`, `getRightTable()`, `getJoinType()`, `getOnClauseSql()`, `getConditionBindParams()`, `getLeftColumns()`, `getRightColumns()`.

    **3. Create `RexToJoinSqlString` -- standalone alias-aware converter for JOIN conditions.**

    Since `RexToSqlString.convertInputRef()` is private, create `RexToJoinSqlString` as a standalone class (NOT extending RexToSqlString) that duplicates the convert/convertCall/convertLiteral delegation logic but overrides the input ref handling. Constructor takes:
    - `RelDataType joinRowType` (the combined row type of the join)
    - `int leftFieldCount` (number of fields in left table's row type)
    - `String leftAlias` (e.g., "t1")
    - `String rightAlias` (e.g., "t2")

    The `convertInputRef(int index)` method:
    - If `index < leftFieldCount`: prefix with `"t1"`, field name from `joinRowType.getFieldList().get(index).getName()`
    - If `index >= leftFieldCount`: prefix with `"t2"`, field name from `joinRowType.getFieldList().get(index).getName()`
    - Quote alias and field name with double quotes: `"t1"."field_name"`

    This class only needs to handle the JOIN condition RexNode (typically comparisons, AND, OR, IS NULL), not the full expression set. Support: EQUALS, NOT_EQUALS, LESS_THAN, LESS_THAN_OR_EQUAL, GREATER_THAN, GREATER_THAN_OR_EQUAL, AND, OR, NOT, IS_NULL, IS_NOT_NULL, and RexLiteral (delegate to BindParam creation same as RexToSqlString). The convert() method should return `RexToSqlResult` with `?` placeholders and `BindParam` list, same as RexToSqlString.

    **4. Add `buildJoinSql()` method to `SqlBuilder`.**

    Add a new public method to SqlBuilder:

    ```java
    public String buildJoinSql(
        String leftSchema, String leftTable, String leftAlias,
        String rightSchema, String rightTable, String rightAlias,
        String joinType, // "INNER JOIN", "LEFT OUTER JOIN", etc.
        String onClause, // the ON condition SQL string
        List<SchemaPath> leftColumns, List<SchemaPath> rightColumns) {
    ```

    Assembly order:
    1. `SELECT` list: `"t1"."col1", "t1"."col2", ..., "t2"."col3", "t2"."col4", ...`
    2. `FROM "leftSchema"."leftTable" AS "t1"`
    3. `{joinType} "rightSchema"."rightTable" AS "t2"`
    4. `ON {onClause}`

    If both leftColumns and rightColumns are null or empty, use `SELECT *` (but this should not happen in practice since projected columns are always known from the scan nodes).

    Use `quoteIdentifier()` for all schema/table/alias names. Use `quoteIdentifier(alias) + "." + quoteIdentifier(col.getRootSegment().getPath())` for column references.

    Also add a static helper `joinTypeToSql(JoinRelType)` that maps:
    - `INNER` -> `"INNER JOIN"`
    - `LEFT` -> `"LEFT OUTER JOIN"`
    - `RIGHT` -> `"RIGHT OUTER JOIN"`
    - `FULL` -> `"FULL OUTER JOIN"`

    **Make `buildJoinSql()` non-final (overridable)** so that `OracleSqlBuilder` can override it if needed (e.g., Oracle does not support `AS` for table aliases in FROM -- the alias syntax is `"TABLE" "t1"` without `AS`). The base implementation uses `AS`. If Oracle integration tests in Plan 03 fail due to `AS`, add an override in `OracleSqlBuilder` that omits `AS`.

    **1. Create `JdbcPushJoinIntoScan` -- LOGICAL phase rule.**

    This rule matches `JoinRel(JdbcScanDrel, JdbcScanDrel)` where both scans share the same source name. This is a LOGICAL-level rule, NOT physical. At logical level, the children are clean JdbcScanDrel nodes with no pushdown state (WHERE, LIMIT, ORDER BY, aggregation are all PHYSICAL-phase concerns), so no declination guards for those are needed.

    ```java
    public final class JdbcPushJoinIntoScan extends RelOptRule {
      public static final RelOptRule INSTANCE = new JdbcPushJoinIntoScan();

      private JdbcPushJoinIntoScan() {
        super(RelOptHelper.some(JoinRel.class,
            RelOptHelper.any(JdbcScanDrel.class),
            RelOptHelper.any(JdbcScanDrel.class)),
            "JdbcPushJoinIntoScan");
      }
    ```

    Use `com.dremio.exec.planner.logical.JoinRel` as the parent match class. This is Dremio's logical join -- a single concrete class, unlike physical level where there are HashJoinPrel, MergeJoinPrel, NestedLoopJoinPrel. One rule covers all join types.

    **`matches()` method -- same-source guard:**
    ```java
    @Override
    public boolean matches(RelOptRuleCall call) {
      JdbcScanDrel left = call.rel(1);
      JdbcScanDrel right = call.rel(2);
      // Same source name = same physical JDBC connection pool.
      return left.getPluginId().getName().equals(right.getPluginId().getName());
    }
    ```

    No aggregation/WHERE/LIMIT/ORDER BY guards needed here because JdbcScanDrel has none of those fields (those are added by PHYSICAL-phase pushdown rules to JdbcScanPrel, which does not exist yet at LOGICAL level).

    **`onMatch()` method:**
    1. Extract `JoinRel join = call.rel(0)`, `JdbcScanDrel leftScan = call.rel(1)`, `JdbcScanDrel rightScan = call.rel(2)`.
    2. Get `JoinRelType joinType = join.getJoinType()`.
    3. Get the join condition: `RexNode condition = join.getCondition()`.

    4. **Extract schema and table from TableMetadata path components** (NOT from scan fields -- JdbcScanDrel has no getSchemaName()/getTableName()):
       ```java
       List<String> leftPath = leftScan.getTableMetadata().getName().getPathComponents();
       String leftSchema;
       String leftTable;
       if (leftPath.size() >= 3) {
         leftSchema = leftPath.get(leftPath.size() - 2);
         leftTable = leftPath.get(leftPath.size() - 1);
       } else if (leftPath.size() == 2) {
         leftSchema = leftPath.get(0);
         leftTable = leftPath.get(1);
       } else {
         leftSchema = "";
         leftTable = leftPath.isEmpty() ? "" : leftPath.get(0);
       }
       // Same extraction for rightScan
       ```
       This is the exact same pattern used in `JdbcScanPrule.onMatch()` (see that file for reference).

    5. Get `int leftFieldCount = leftScan.getRowType().getFieldCount()`.
    6. Convert join condition to SQL using `RexToJoinSqlString`:
       ```java
       RexToJoinSqlString converter = new RexToJoinSqlString(
           join.getRowType(), leftFieldCount, "t1", "t2");
       RexToSqlResult condResult = converter.convert(condition);
       if (condResult == null) return; // unsupported condition, decline pushdown
       ```
    7. Determine projected columns for each side from `leftScan.getProjectedColumns()` and `rightScan.getProjectedColumns()`. If null, derive from rowType field names.

    8. Create `JdbcJoinScanDrel` with all raw components:

       JdbcJoinScanDrel joinScanDrel = new JdbcJoinScanDrel(
           join.getCluster(),
           leftScan.getTraitSet(),  // keep LOGICAL convention
           leftScan.getPluginId(),
           leftSchema, leftTable,
           rightSchema, rightTable,
           joinType,
           condResult.getSql(),  // ON clause SQL with ? placeholders

    **IMPORTANT: The JdbcJoinScanDrel needs a corresponding JdbcScanPrule-style conversion to physical.** Add a static inner `Prule` class (or separate class) that matches `JdbcJoinScanDrel` and converts to `JdbcJoinScanPrel`:

    ```java
    public static final class JdbcJoinScanPrule extends RelOptRule {
      public static final RelOptRule INSTANCE = new JdbcJoinScanPrule();
      private JdbcJoinScanPrule() {
        super(RelOptHelper.any(JdbcJoinScanDrel.class), "JdbcJoinScanPrule");
      }
      @Override
      public void onMatch(RelOptRuleCall call) {
        JdbcJoinScanDrel logical = call.rel(0);
        JdbcJoinScanPrel physical = new JdbcJoinScanPrel(
            logical.getCluster(),
            logical.getTraitSet().replace(Prel.PHYSICAL).plus(DistributionTrait.SINGLETON),
            logical.getPluginId(),
            logical.getLeftSchema(), logical.getLeftTable(),
            logical.getRightSchema(), logical.getRightTable(),
            logical.getJoinType(),
            logical.getOnClauseSql(),
            logical.getConditionBindParams(),
            logical.getLeftColumns(), logical.getRightColumns(),
            logical.getRowType());
        call.transformTo(physical);
      }
    }
    ```
