<objective>
Create a LiteralInliner utility that replaces bind parameter placeholders with properly-escaped SQL literals, and wire it into AdbcRecordReader to enable the PostgreSQL ADBC driver's fast COPY binary protocol.

Purpose: When bind parameters are sent via stmt.bind() the ADBC PG driver uses the Extended Query Protocol (parse/bind/execute), which cannot use COPY binary. By inlining literals directly into the SQL string, the driver uses the simple query protocol, routing through the faster COPY binary path.

Output: LiteralInliner utility class, modified AdbcRecordReader.setup(), comprehensive unit tests with SQL injection safety verification.
</objective>

    **1. Create `LiteralInliner` -- a utility class for converting SQL-with-`?` placeholders to SQL-with-inlined-escaped-literals.**

    Package: `com.dremio.plugins.jdbc.planning`
    The class has two static methods:

    ```java
    public final class LiteralInliner {
      private LiteralInliner() {} // utility class

      /**
       * Replaces each ? placeholder in the SQL with the corresponding BindParam's
       * properly-escaped SQL literal representation.
       */
      public static String inlineBindParams(String sql, List<BindParam> params) { ... }

      /**
       * Converts a single BindParam to its SQL literal string representation.
       * Visible for testing.
       */
      static String toSqlLiteral(BindParam param) { ... }
    }
    ```

    **`inlineBindParams` implementation:**
    - Iterate through the SQL string character by character.
    - When encountering `?` and `paramIdx < params.size()`, replace with `toSqlLiteral(params.get(paramIdx++))`.
    - Otherwise, append the character as-is.
    - If `params` is null or empty, return the original SQL unchanged.

    **`toSqlLiteral` implementation -- type dispatch:**

    | BindParam typeName | Format | Example |
    |---|---|---|
    | `null` value | `NULL` | `NULL` |
    | TINYINT, SMALLINT, INTEGER, BIGINT | raw `value.toString()` | `42` |
    | FLOAT, REAL, DOUBLE | raw `value.toString()` | `3.14` |
    | DECIMAL | raw `value.toString()` | `99.99` |
    | VARCHAR, CHAR | `'` + escape(`value.toString()`) + `'` | `'O''Malley'` |
    | BOOLEAN | `TRUE` or `FALSE` (direct keyword) | `TRUE` |
    | DATE | `DATE '` + format + `'` | `DATE '2024-01-15'` |
    | TIME | `TIME '` + format + `'` | `TIME '14:30:00'` |
    | TIMESTAMP | `TIMESTAMP '` + format + `'` | `TIMESTAMP '2024-01-15 14:30:00.0'` |
    | default (unknown) | `'` + escape(`value.toString()`) + `'` | safe fallback |

    **String escaping rule:** ONLY escape single quotes by doubling them: `'` -> `''`. Do NOT escape backslashes. PostgreSQL uses `standard_conforming_strings=on` by default since 9.1, meaning backslash is NOT an escape character in standard `'...'` string literals. Only `E'...'` strings treat backslash as escape.

    **Date/Time/Timestamp formatting:** BindParam stores these as epoch millis (Long per Phase 33-01 decision). Convert using:
    - `new java.sql.Date(((Number) value).longValue()).toString()` for DATE (yields `YYYY-MM-DD`)
    - `new java.sql.Time(((Number) value).longValue()).toString()` for TIME (yields `HH:mm:ss`)
    - `new java.sql.Timestamp(((Number) value).longValue()).toString()` for TIMESTAMP (yields `YYYY-MM-DD HH:mm:ss.SSS...`)

    if (hasParams) {
      // ADBC-02: Inline literals directly into SQL for COPY binary protocol.
      // The ADBC PG driver uses the simple query protocol when no bind params are set,
